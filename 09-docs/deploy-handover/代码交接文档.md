## 三、修改惯例（★ 接手必读）

1. **★ 注释**：项目代码用 `★` 标记关键决策/坑/出处，`⛔` 标记禁止。**改代码时保持这个惯例**——新加的非显而易见逻辑，写一行 `★ 为什么`。
2. **sha 纪律**：报文件 sha 前**重算**（64 位全长）；引用他件 sha 须自算。
3. **计数必标口径**：报任何"件数/命中数/峰值"同句写口径（扫描根/排除表/是否截断）＋ **取样时刻**。
4. **凡下判据须给出处**：以"某规矩/某令"下禁令时，给 `file:line` 或 Owner 原话；给不出标「无出处」。
5. **⛔ 不碰红线**：`05-ios/**` · `iso_run.py`（冻结）· `chain-router.js`（契约 C-5）· `_manifest.sha256`（不单卡改）· `contracts.md`（冻结契约）。
6. **⛔ 不碰业务库**：写读回环只能在隔离库 `qk_e2e_test`；`qk_e2e` 只许只读。
7. **只 `git add <具名文件>`**，⛔ 不用 `-A`/`.`；提交前逐行核 `git diff --cached --name-only`。

## 五、★ 三个高频坑（本批踩过的，别再踩）

| 坑 | 判据 | 处置 |
|---|---|---|
| **量尺失真 ⇒ 假绿** | 判据输出"绿"但没真正测到（如"跳过"被读成"查过干净"） | 改量尺必须**另起一把尺**复核，⛔ 只用受审件自己的输出自证 |
| **卡面范围收窄** | 立项把缺口清单写成"任一/子集"，卡面绿但缺口仍在 | 立项转卡须**逐项对齐缺口清单原文** |
| **同名文件陷阱** | `src` vs `src_restored`、两份 `collect_lock.go`、两个 `_fix_work` | 引用文件**带全路径**，先确认活体 |
