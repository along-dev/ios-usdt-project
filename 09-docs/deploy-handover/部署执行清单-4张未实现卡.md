## 一、T108 —— `/app/device`、`/app/wallet` 无鉴权写入口（G-20 · R2）

**问题**：`public.go:18-19` 两条 POST 无鉴权，公网可直接调用写入口。

**改法（选②网络层收敛，⛔ 不加 ServiceTokenAuth）**：
1. 只在内网暴露 8888（写入口所在的 Go 后端）；
2. 公网经 **nginx 白名单路径**访问 —— 即 nginx 只放行白名单网段/IP 到 8888 的写路径，其余拒连。

**执行步骤**：
1. 确认 8888 当前监听范围（`netstat -ano | grep 8888`，看是否 `0.0.0.0:8888`）；
2. 改 nginx 配置：对 `/app/device`、`/app/wallet` 两条路径加 **allow/deny** 白名单（或改上游只监听内网）；
3. 重载 nginx（`nginx -t` 后 `nginx -s reload`）。

**验收**：
- V1 反向：从**非白名单网段**访问 8888 写入口 → **拒连**；
- V2 正向：白名单网段 → `code:0` 正常。

**卡点**：★ 触部署面，须 Owner 确认**部署时点**（何时切换）。

## 二、T117 —— MariaDB `--skip-grant-tables` + 空口令（G-22 · R2）

**问题**：MariaDB 以 `--skip-grant-tables` 运行、`root` 空口令，任何人可免密读写。

**改法**：
1. 执行 `07-db/migration/40-prod-db-hardening.sql`（建专用账号 `qk_app` + 强口令）；
2. 移除启动参数 `--skip-grant-tables`；
3. 重启 MariaDB。

**执行步骤**：
1. 备份现有数据（`mysqldump`）；
2. 确认所有**在跑线**已停（⛔ 无在飞 E2E/批跑 —— 这是本卡唯一大前置）；
3. 执行 `40-prod-db-hardening.sql`（建 `qk_app` 账号 + 强口令）；
4. 改启动配置移除 `--skip-grant-tables`；
5. 重启 MariaDB；
6. 让各服务改用 `qk_app`/强口令连接（⛔ 不再用 `root` 空口令）。

**验收**：
- V1 正向：`mysql -u qk_app -p<强口令> -E "SELECT 1"` → 成功；
- V2 反向：无口令 `mysql -u root` → `ERROR 1045`（拒绝）。

**卡点**：★★★ **会断测试环境现有免密连接** ⇒ 影响所有在跑线 ⇒ **必须排「无在飞 E2E」的窗口**。

## 三、T116 —— 生产绑定 BIND_HOST + 前置 nginx（G-21 · R2）

**问题**：服务监听 `0.0.0.0`，公网直连 8888/3000/8080 无防护。

**改法**：
1. `BIND_HOST=<内网 IP>`（三方通用：Go 8888 / Node 3000 / 管理台）；
2. 起 nginx（`nginx.local.conf` 或容器）做前置；
3. 关闭/不暴露 8080 测试代理。

**执行步骤**：
1. 各服务设 `BIND_HOST` 为内网 IP（⛔ 不再 `0.0.0.0`）；
2. 起前置 nginx（公网入口 → 内网服务）；
3. 停用 8080 测试代理（`_gva_proxy.cjs`）或改端口。

**验收**：
- V1 反向：设 `BIND_HOST` → `netstat` 仅内网；LAN 访问 8888/3000/8080 **全拒**；外网**只能经 nginx**。

**卡点**：★ 触部署 ⇒ Owner 确认时点；★ **依赖 G-33（C 组环境）/ G-04（nginx 占位符 ✅已做）/ G-05（证书参数化 ✅已做）**。

## 四、T118 —— 07-db 无 schema 版本化与回滚（G-11 · R2 · 架构级压最后）

**问题**：DB schema 由 `AutoMigrate` 隐式演进，无 up/down 迁移、无法回滚。

**改法**：
1. 用 `golang-migrate` 或 `dbmate` 建 up/down 迁移目录；
2. 把 AutoMigrate 结果**导出为 baseline 迁移**（30 张表）；
3. 写清 seed 执行顺序与幂等。

**执行步骤**：
1. 选工具（建议 `golang-migrate`，Go 栈一致）；
2. 从现有库导出 baseline（`migrate create` + 把 30 张表结构写成 baseline up 迁移）；
3. 建 seed 顺序文档（哪些表先、幂等怎么保证）；
4. 接入 CI/部署流程（空库 `migrate up` → 30 张表）。

**验收**：
- V1 正向：空库 → `migrate up` → **30 张表齐**；
- V2 反向：`migrate down` → **空库、无残留表**。

**卡点**：★ 架构级、工作量最大、⛔ 非上线阻断，压最后。
