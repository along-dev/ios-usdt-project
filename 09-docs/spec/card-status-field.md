## 〇、为什么需要这个字段（问题陈述，非主张）

现状：`09-docs/cards/` 的 **154 张卡**没有可机读的状态。本线实测**三种机械判法全部失败**：

| 判法 | 失败原因（实测） |
|---|---|
| 读卡内自述 | 卡片**保留历史文本**：`T31` 已关单（`L053`），卡里仍留立卡时的「只立卡、未落码」 |
| 读台账**文件名** | 收口类命名混用（`L019-D2阶段台账` vs `L045-…完整收口台账`） |
| 读台账**正文**（行级／窗口级） | 行级 ⇒ **96/154 判不出**；±160 字符窗口 ⇒ **过判成 99 张 DONE**（＝本项目所禁的「看起来通了」） |

⇒ 结论：**唯一可机读的事实源，必须是卡片自己携带的结构化字段。**

## 二、★ 字段规格（**建议**）

### 2.1 落点：**正文内的单行块**，`# 标题` 之后的第一个空行前

不引入 YAML frontmatter，改在**标题正下方**放一段**定长、可正则**的行块。理由：不触碰文档其余部分、与现有体例兼容、且**diff 恒为 1 处插入**。

```markdown
# T41 —— AD-10 删除死代码 AppJWTAuth 整套中间件

> **status**: CARD_ONLY
> **evidence**: -
> **line**: 后台线
> **updated**: 2026-10-06
```

### 2.2 四个键（**全部必填**，缺一即红）

| 键 | 取值 | 说明 |
|---|---|---|
| `status` | **枚举 6 值**（见 2.3） | 唯一权威状态 |
| `evidence` | **commit SHA（≥7 位）** ／ `verify_*.py` 脚本名 ／ 台账号（`L0NN`）／ **`-`** | `DONE` 时**不得为 `-`** |
| `line` | 线名，或 `未标` | 取 `CH-00` 地址簿的线名 |
| `updated` | `YYYY-MM-DD` | 状态**最后变更**日 |

### 2.3 `status` 枚举（**6 值，封闭集**）

| 值 | 含义 | 判据（谁有权写） |
|---|---|---|
| `DONE` | 已关单 | 台账有关单记录；**`evidence` 必填** |
| `IN_FLIGHT` | 在执行或复核中 | 台账记「在飞」 |
| `CARD_ONLY` | 只立卡、未落码 | 卡面自述 |
| `BLOCKED` | 阻塞（含等 Owner 授权） | 卡面自述 |
| `SUPERSEDED` | 被后续卡取代 | 台账记录 |
| `UNKNOWN` | **未判**（**允许存在**） | 见 2.4 |

### 2.4 ★ `UNKNOWN` 必须保留为**合法值**

**理由**：把"没核实"硬塞进 5 个确定值里，就是**制造假信号**（本项目 `E-3xx` 族）。
⇒ 规格**允许** `UNKNOWN`，且**要求**：`status: UNKNOWN` 的卡**不得**被当成"待办"或"已完成"派活。

## 三、门禁怎么校验（`AD-05` 第二半的输入）

字段一旦存在，`verify_doc_freshness.py` 可**新增三条断言**（**建议，须另批实施**）：

| # | 断言 | 失败表现 |
|---|---|---|
| **A1** | 每张 `09-docs/cards/*.md` **必须**含 4 键（非任务卡在**白名单**内豁免） | 缺键 ⇒ 红 |
| **A2** | `status` ∈ 6 值枚举；`updated` 匹配 `YYYY-MM-DD` | 越界／格式错 ⇒ 红 |
| **A3** | **`status: DONE` ⇒ `evidence != "-"`** | 有 DONE 无证据 ⇒ 红 |

★ **A3 是这套规格的核心价值** —— 它把「声称完成」与「拿得出锚」绑定。

## 五、★ 拿不准的（**如实，⛔ 不替 A 归一**）

1. **`evidence` 该不该强制到 `verify_*.py`？** —— 很多老卡的证据是**台账号**而非脚本（`F1-C7`、`I3-C3`、`W1-C2` 都只有台账）。**本线拿不准**是否该要求补脚本，**故规格只要求"非 `-`"**，由 A 定严度。
2. **非任务卡怎么处置**（`V0-*`、`R-全量上线审核总纲`、`_待批_*`、`_总调度启动提示词`）——
   **选项**：(a) 白名单豁免；(b) 从 `cards/` 移出到别处；(c) 也加字段但 `status: UNKNOWN`。
   **本线倾向 (a)**，但**移出目录会动既有引用**，故 **⛔ 不代裁**。
3. **`line` 的取值域**是否要固定枚举？—— 现在线名有「后台线／后台线（接班人）」等**带后缀变体**，**本线拿不准**该归一还是照实记。
4. **本规格未覆盖**：`09-docs/ledger/` 与 `09-docs/reports/` 的时效字段 —— `AD-05` 后半（门禁扩到台账/索引/README）**需要先定这两处的字段**，**本线尚未出**。
