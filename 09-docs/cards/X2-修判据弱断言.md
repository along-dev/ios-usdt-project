## ★★ 分类处置（**这是本卡的关键**）

### A 类：**过宽断言**（必须修）

**#1 `st7 != 404`**：

**问题**：该断言**只要不是 404 就算过** ⇒ **401/500/任意状态码都能通过** ⇒ **无判别力**。

**修法**：**改为断言确切状态码**。

**★ 调度已实测 `${ADMIN}/logout` 的确切行为**（消除停靠点 1）：

```
logout(带 token): HTTP=302
logout(无 token): HTTP=302
```

**⇒ 确切期望值 = `302`**（不论是否带 token）。

**⇒ 断言改为 `st7 == 302`**（**不是** `st7 != 404`）。

### B 类：**硬编码 True**（须改为自证式）

**#2/#3/#4/#5 都是 `rec(..., True, ...)`** ⇒ **无条件通过**。

**但它们的性质不同**：

| # | 断言名 | 性质 | 正确修法 |
|---|---|---|---|
| **#2** | "D5 apk/list 排序" | **条件分支里的兜底**（APK 数 < 2 时无法判序）| ★ 改为 **SKIP 标注**（**P-13：SKIP ≠ PASS**）|
| **#3** | "P7c 双用途事实已如实登记" | **元断言**（检查"是否登记了"）| ★ 改为**真正检查输出中存在该登记** |
| **#4** | "P7c 投递集与参照集内容不同" | **条件分支兜底** | ★ 改为**真实的集合比较** |
| **#5** | "V6 已如实声明未真编译" | **元断言** | ★ 改为**检查类常量/输出中存在该声明** |

**⇒ 统一原则**：
- **能真断言的 ⇒ 真断言**（如 #4 的集合比较）
- **无法判定的 ⇒ 标 SKIP**（如 #2 的"APK < 2 无法判序"）—— **不得报 PASS**
- **元断言（#3/#5）⇒ 改为检查"声明确实存在"**（如 grep 类常量/输出）

★ **这直接呼应 P-13（SKIP ≠ PASS）与 P-25（判据可能是"空过"）。**
