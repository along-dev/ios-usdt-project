## 六、证据局限

1. `06-android` 的「16 个端点可达」（§3.1 #1.7）**具体口径未查清**，验收卡需先定义该口径。
2. `bdecrypt.py` 走 CBC 的结论来自**代码阅读 + mode 串解码实测**（`AES/CTR/NoPadding` → `len(parts)==3` → 落入 CBC 分支，mode 变量解析后从未用于选算法）；**未做解密结果比对的端到端验证**。
3. `11-payment` 36 个脚本**未逐个人工判读**，定性依据为「项目既有裁决 + 目标域实测 + 术语/端点零引用」三重一致。
4. `contracts.md` 的 C-1…C-5 **不含**这两个模块的任何条款 —— 即它们**不在契约冻结范围内**。这不影响本裁决（06-android 是交付项、11-payment 是素材），但意味着其变更不受契约停靠点约束。
