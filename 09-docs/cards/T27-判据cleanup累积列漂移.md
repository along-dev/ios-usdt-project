## 一 · 问题（一句话）

卡A 阶段2 起，**创建 bill 时会在同一事务内把利润累加进 `custom.usdt_num` / `agent.usdt_num`**；

### 9.1 改法（**反向减回**）

三个判据的 `cleanup()` 一律改为 **先反向减回、再删行**：

```sql
UPDATE <custom|agent> t JOIN (
  SELECT s.user_id AS uid, SUM(b.usdt_num) AS amt
  FROM bill b JOIN settlement s ON s.id = b.settlement_id
  WHERE b.role = <2|3> AND b.transfer_hash LIKE '<本脚本专属前缀>%'
  GROUP BY s.user_id) x ON t.user_id = x.uid
SET t.usdt_num = COALESCE(NULLIF(t.usdt_num,''),0) - x.amt;
```

★ **为什么 `settlement.user_id` 是正确的回减键**（实测已核，非推断）：卡A 阶段2 的累加 target ＝
role=2 → `customUserIdForWallet()` ＝ `packet.custom_user_id`；role=3 → `agentSettlement.UserId`；
而**这两个值都等于该 bill 的 `settlement_id` 所指向行的 `user_id`**（`06` 设计件 (g) 与代码一致）。
