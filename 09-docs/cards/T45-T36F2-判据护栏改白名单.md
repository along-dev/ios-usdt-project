## 一 · 缺陷（**总调度第四任现读树外件，非转述**）

`T36` 给 5 件判据加的 fail-closed 护栏是**黑名单式**（只拒绝**已知**的那个坏值）：

```python
# verify_f1c9_toaddress_guard.py:51-52（同形出现在 f1c8 / money_path / t31）
DB_NAME = os.environ.get("DSH_DB", "qk_e2e")
assert DB_NAME != "qk_e2e", "⛔ 拒绝裸跑：DSH_DB 落回业务库（须经 iso_run.py 注入 qk_e2e_test）"
API = os.environ.get("DSH_API", "http://127.0.0.1:8888")
assert ":8888" not in API, "⛔ 拒绝裸跑：DSH_API 落在共享实例（须经 iso_run.py 注入 8900）"
```

**绕过向量**（`assert` 是**精确串比对**）：
1. ★ **大小写变体**：`DSH_DB=QK_E2E` ⇒ `"QK_E2E" != "qk_e2e"` 为真 ⇒ **放行**；而 **Windows 上 MySQL 库名<ins>不分大小写</ins>** ⇒ `USE QK_E2E;` **仍打业务库**。★ 这是复核报出的那一条。
2. ★ **任何"别的值"都放行**：`DSH_DB=qk_e2_`（笔误）· `DSH_DB=qk_e2e `（尾随空格）· `DSH_DB=""`（空串）… ⇒ **全部放行**，随后 `USE <该值>`。
   ⇒ 根因：**护栏是"拒绝一个坏值"，不是"只允许一个好值"** —— **不是 fail-closed**。

★ **事实源**：`iso_run.py:39` `DST_DB = "qk_e2e_test"`、`:312` `env={..., "DSH_DB": DST_DB, "DSH_API": ISO_API}` ⇒ **经 `iso_run.py` 跑时，`DSH_DB` 恒为 `qk_e2e_test`、`DSH_API` 恒为 8900**。

---

## 二 · 目标

护栏改为**白名单（fail-closed）**：**只放行隔离实例注入的那组值**，其余一律**在任何副作用之前**拒绝。
