### 7.2 ★ 补进范围的**语义口径**（不然本卡「绿了也不满足 C-6」）

**问题**：串行重读是 `tx.Where("transfer_hash = ?", req.TxHash).Limit(1).Find(&exist)` —— **无 role 过滤、无 `ORDER BY`** ⇒ 返回**任意一行**（可能是 role=2/3/4）。而 **C-6 要求「首次的 `bill` id」**（`09-docs/spec/contracts.md:120-134`，实读），且代码自己的注释就写着「**role=1 平台（本函数返回其 ID 作为主 bill）**」（`collect_result.go` §⑤-b）。

**裁定**：**两条路径（串行重读 ＋ 并发捕获后的重读）统一返回「首次那笔」**，取：

```go
// 「首次那笔」＝ 同一 transfer_hash 下 id 最小者
//   public（Region != 2）：role=1 先插 ⇒ id 最小者即 role=1（＝首次提交时返回给调用方的那笔）
//   private（Region == 2）：只落 role=4 **一行** ⇒ 同一结论成立
tx.Where("transfer_hash = ?", req.TxHash).Order("id ASC").Limit(1).Find(&exist)
```

★★ **⛔ 不得硬编码 `AND role = 1`** —— **私域（`wallet.Region == 2`）不写 role 1/2/3、只写 role=4**（`collect_result.go` §⑤-a）⇒ 硬编码 role=1 会让**私域重复提交的幂等彻底失效**。
（★ 此点系总调度复核取证建议时**推翻**：取证原建议为 `AND role = 1`。**取证结论对、建议错**，按 `P-54`「采纳结论、修正理由」。）
