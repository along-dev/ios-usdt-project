## D-2 · `10-sweeper` 是否接入主系统互斥

**裁决：保持离线 + 登记为操作规程约束（选项 c2）。**

| 项 | 内容 |
|---|---|
| 事实 | `10-sweeper` 全模块 grep `collect-lock\|collect-release\|acquireLock` → **零命中**；`--broadcast` 可**真广播**，与另两条路径无技术互斥 |
| **理由** | `10-sweeper` 是**离线命令行工具**。接入互斥会把它变成**必须联网**的工具，改变其使用形态；而"人工不并行"是本项目**已在用**的做法 |
| **接受代价（残余风险）** | 三条归集路径**无技术互斥**；若被高频/自动化调用，存在**重复归集**风险，**依赖操作规程兜底** |
| 落地 | 本文件 + `10-sweeper/README.md` 须写明"**广播前必须确认另两条路径无在途归集**"（由 `I3-C3` 承接） |
| **触发复审条件** | 若 `10-sweeper` 被改为**自动/高频**调用 ⇒ **本裁决失效，须重裁** |

## D-3 · iOS 17.3–18.3 空白区处置

**裁决：先灰度实测（选项 c3），不改偏移表。**

| 项 | 内容 |
|---|---|
| 事实 | ① `group.html` 唯一门禁是**下界**（`if (13E4 > iOSVersion) return 1001;`），**无上界**；② 偏移表**累积应用** ⇒ 17.3/17.6/18.0/18.3/18.6 命中条目**完全相同**，等于 **17.0 配置**；③ `index.html` 的 `DEVICE_VERSIONS` 是 `Math.random()` **伪造演示数据**，非投放入口 |
| **理由** | 累积应用语义下**改表会波及所有 ≥ 该版本的版本**，必须回归 15.x–17.2 既有行为；而实测成本低于改表风险 |
| **接受代价** | 17.3–18.3 维持**静默复用 17.0** 的现状 |
| **补充要求** | 必须**加显式告警**（不改行为，只让"静默"变"可见"）—— 由 `I1-C3` 的 V3 用例承接 |
| **触发复审条件** | 灰度实测出结论后重裁（Stage1 成功 → 补 Stage2/3 偏移才有意义；失败 → 整段放弃） |
