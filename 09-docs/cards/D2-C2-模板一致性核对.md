# D2-C2 [R1] 两处 `templates` 的一致性核对

## ★★ 结论先行：**一致性正确，无需修改**

## 目标与定位

方案 `:232` 的原始描述：

> **D2-C2** | 确认 `04-landing/ios-templates`(98) 与 `02-backend-node/templates`(118) 的一致性
> （★ L2 已查明：**不是空的**，运行时读后者；本卡**降级为防 P-2 的一致性核对**）| R1

**⇒ 本卡是**只读核对**，不修改任何文件。**

## 实测事实（2026-09-30）

| 目录 | 文件数 | 定位 |
|---|---|---|
| `04-landing/ios-templates` | **98** | 只读参照（**不参与运行时**） |
| `02-backend-node/templates` | **118** | ★ **运行时读这个**（Node 的 `process.cwd()/templates`） |

### ★ 关系：**A ⊂ B**

| 项 | 数量 |
|---|---|
| 共有 | **98**（= A 的全部） |
| **仅 A 有** | **0** |
| **仅 B 有** | **20** |

### "仅 B 有"的 20 个 = **全部是 I1-C2 的载荷同步产物**

| 目录 | 数量 | 契约依据 |
|---|---|---|
| **`coruna/`** | **15** | **契约 C-3**（coruna entries 恰 15） |
| **`darksword/`** | **5** | **契约 C-3**（darksword entries 恰 5） |

★ 这 20 个由 **I1-C2** 添加（`syncChainPayloads()` 写入 `02-backend-node/templates/{coruna,darksword}/`），
**与 `04-landing/ios-templates` 无关**（后者是 iOS 侧的参照副本）。

**⇒ 差异完全合理：B 是"运行时目录"，含 A 的全部 + 20 个载荷文件。**

## ★ 判据（`verify_d2c2_templates_consistency.py`）：**6/6 GREEN**

| # | 断言 | 结果 |
|---|---|---|
| **C1** | **A ⊆ B**（A 的文件 B 全有） | ✅ 仅 A 有 **0** |
| **C2** | 仅 B 有的 = **预期载荷文件（20 个）** | ✅ 与预期**完全一致** |
| **C3** | **共有部分内容一致**（抽样 20 个，比 sha256） | ✅ 全部一致 |
| **C4** | `coruna` 载荷 = **15**（契约 C-3） | ✅ |
| **C4** | `darksword` 载荷 = **5**（契约 C-3） | ✅ |
| **C5** | B 下无 `apk/` 测试残留（`evil*`/`plain*`） | ✅ |

★ **C5 是本卡附加的价值**：它把"运行时目录被测试数据污染"变成**可检测**的。

## ★ 方法要点（防 P-2）

**按完整相对路径比对**（`os.path.relpath`），
**不按文件名**（本项目已发生过 `routes/auth.js` vs `middleware/auth.js` 同名混淆）。

## 不在范围

- **不改任何文件**（纯验证）
- 不合并两个目录（它们**定位不同**：一个是参照，一个是运行时）
