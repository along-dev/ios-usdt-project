# R1-C3 [R1] `verify_f1c5_runtime.mjs` 模块解析失败（脚本位置问题）

## ★★★ 缺陷事实

### 现象（源卡实测）

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'fastify'
imported from E:\ios漏洞\_integration\_fix_work\verify_f1c5_runtime.mjs
```

### ★★★ 根因（**调度实测，脚本自带注释已说明**）

**`verify_f1c5_runtime.mjs:6` 的原文注释**：

```
★ 本脚本需在 02-backend-node 目录下运行（那里有 node_modules）。
  ESM 在 Windows 下不接受 'E:\...' 形式的绝对路径，故用相对导入。
  运行：cd E:\USDT项目\02-backend-node && node <本脚本的副本>
```

**实测证据**：

| 项 | 值 |
|---|---|
| **`fastify` 的实际位置** | `E:\USDT项目\02-backend-node\node_modules\fastify` ✅ **存在** |
| `_fix_work\node_modules\fastify` | ❌ 不存在 |
| `_integration\node_modules\fastify` | ❌ 不存在 |
| **脚本的相对导入** | `'./src_restored/plugins/api/routes/landing.js'`（**相对 `02-backend-node`**）|

**⇒ ESM 的模块解析从【脚本所在目录】向上找 `node_modules`；
而脚本在 `_fix_work` ⇒ 找不到 `fastify`。**

**★ 脚本的作者**已经知道**这一点（注释里写明"须在 02-backend-node 下运行"），
但**脚本本身仍放在 `_fix_work`** ⇒ **直接 `node _fix_work/...` 必失败。**

## ★★★ 推荐实现（**基于实证**）

```js

import { createRequire } from 'node:module';

const REPO = 'E:/USDT项目/02-backend-node';

// 方式 3（推荐）：createRequire 以【产物 package.json】为基准解析
```
