## 四、你的固定动作（每张卡，12 步）

1. **基线检查**：确认在 `E:\USDT项目`、工作区无未授权改动。不符 → 停。
   （**无 git，故无"当前分支"可查**；改为核对卡片的 `base` 内容 sha256 与现树逐文件相符）
2. **【定档】** 按 §1 给 R0–R3，**写下理由**（命中哪条触发条件 + 门禁强度事实）。定不出 → 按更高一档。**不写理由视为未定档。**
3. **取内容基线快照**：逐文件记录 sha256 + bytes + eol，写入卡片 `base`（**无 git，不建分支/工作树**）
4. **`task_branch` 写「无」**
5. **派执行者**：`references/prompts.md`【提示词二】稳定前缀 + 卡片全文 + **副本路径**
   - ★ **一卡一份仓外副本**（必须含 `node_modules` / 运行产物）
   - ★ **必须显式声明**：副本从哪来（源路径 + 取副本时刻 + 关键产物 sha256）
6. **【复核】自己重跑**该卡 verify，取**你自己会话里的真实退出码**，与执行者自报逐位比对。不一致 → 未通过，退回。
   **取退出码不接管道**：`cmd > /dev/null 2>&1; echo $?`（PowerShell 用 `echo "EXIT=$LASTEXITCODE"`）
7. **提交**：**本项目无 git → 提交动作改为「确认副本内容 sha256 + 写入台账」**
8. **派审核**：R0 不派；R1 派 1 名（可波次末批量 3–5 张）；R2 派 2 名（**A 审 diff 内部 / B 审跨件关系，互不可见，当场派**）；R3 再加 1 名专项（安全/权限）**或按停靠点交 Owner**
9. **处置 Finding**：P0/P1 → **停下升级 Owner，不自动修订**；P2 → 退回重跑第 6、7 步；P3 → 登记不阻断；两轮未解 → 逐条裁决记理由；**双审分歧不取并集不取交集，由你裁决留痕**
10. **内容 sha256 一致核对**：**同一内容 sha256 必须在「派审 / 审核 / 批准」三处一致**，任一不等报 `BLOCKED_CONTENT_MISMATCH` 不合并。**审核后内容 sha256 变化必须重审。**
11. **合并**：因无 git，**"合并"= 把审过的副本内容采纳为产物**；冲突 → 中止进 BLOCKED，**不手工硬解**
12. **台账 + 清理**：追加一行（档位与理由 / 副本来源 / 三处内容 sha256 / verify 证据 / Finding 与分歧处置摘要）；写完顺手看台账余量，低于阈值就拆
