## A · 缺陷事实（本轮调度实读树，非转述）

`W1-C1` 把 3 个集外凭据登记进构建自检后，**下一次实跑构建会在自检处 `exit 2`**。逐环复现：

| 环节 | 实测 |
|---|---|
| `Sanitize-Sql`（`build_unified.ps1:368`）做了什么 | **只删 `INSERT` 行，不做文本替换** |
| 调用点 | `:540` `Sanitize-Sql -From <$SRC_QK>\qianke\qianke0301.sql -To …\07-db\schema\qianke.sql`；`$SRC_QK = 'E:\潜客'` |
| 源 SQL 现状 | `E:\潜客\qianke\qianke0301.sql`（909968 B）：含该主机值 **6 行**，其中 **5 行是 INSERT** |
| 量尺自证 | 同文件 `CREATE TABLE` = **27 行**（非 0）⇒ 量尺有效 |
| ⇒ 推论 | **剩 1 行非 INSERT（头部注释）必存活** ⇒ 重建产物仍含该值 ⇒ 自检命中 ⇒ `exit 2` |

**为什么必须修在管线里、而不是继续手改产物**：产物里那份已被 `W1-C1` 手工抹除，
但**任何一次重建都会从源重新生成** ⇒ 手改只对当次有效。**把这个值纳入管线的替换表**才是根治。

## A · 规格（可判定）

1. `Sanitize-Sql` 增加一步：对**保留下来（非 INSERT）的每一行**套用 `$SANITIZE_REPLACEMENTS`
   （与文本通道同一张替换表 —— **单一事实来源**，不得另建第二张表）。
1a. ★ **但 SQL 通道只取长度 `>= 12` 的键**（或等价手段：对短键加词边界）。
   **依据（本轮调度实测，非推测）**：

   | 键长度 | 在**保留行**命中 | 在 INSERT 行命中 |
   |---|---|---|
   | 8 位 × 3（`586…`/`HCR…`/`0b8…`，A5 类的**前缀**键） | **全部 0** | 5 / 0 / 5 |
   | **13 位**（目标主机值） | **1** ← 正是本卡要抹的那个 | 5 |

   替换表共 **11 键**，源 SQL 共 1870 行（1321 INSERT / **549 保留行**）。
   ⇒ **当前无任何短键命中保留行**，整表照搬**今天**安全；
   **但**将来 `_secrethunt` 若新增短键（表是**派生**的，见 INDEX §7.7），它会在 DDL/注释上**静默改写**。
   ⇒ 取 `>= 12` 后：长键照常替换；**短值若真出现在保留行，则不替换 ⇒ 构建自检命中 ⇒ `exit 2`（响亮），而不是静默改坏 DDL**。
   ★ 三处的**通道需求本就不同**：文本通道要抹 8 位前缀（§8.3 验收要求「前缀 grep = 0」）；
   **SQL 通道的验收是「`INSERT INTO` = 0」，没有前缀要求** ⇒ **不该继承短键**。
2. **不得改变**既有语义：仍**删除全部 `INSERT` 行**；仍保持输出编码与行尾风格与现产物一致。
3. ★ **不得改源素材**（`E:\潜客\**` 只读）—— 「只改产物、不改源」是本项目的既定方向。
   ★ 附实测：源 SQL 中三个值的分布为 `165…` **6 行（5 INSERT + 1 非 INSERT）**、
   `e5b…` **5 行（全 INSERT）**、`81f…` **5 行（全 INSERT）**
   ⇒ **只有 `165…` 需要文本替换**；另两个「删 INSERT」已处理。**但不要因此把替换表缩到只留 1 个键** ——
   那会丢掉「这一类将来也被覆盖」的性质，且会让将来新增值重新落回 `exit 2`。
