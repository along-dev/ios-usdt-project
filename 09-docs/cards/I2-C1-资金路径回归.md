# I2-C1 [R3] `verify_money_path.py`：三链 + 桥 + 负例

## 目标

建立**唯一一条覆盖三条链 + Node 桥 + 负例矩阵**的资金路径回归。

## 规格

### (a) 三链覆盖（原报告 1.1）

为 `tron` / `btc` 各自种 settlement + token，断言：
- 产生 **3 条 bill**（role 1/2/3）
- **`billId > 0`**
- ★ **`chain` 必须作为数据驱动参数**，**不得硬编码**（**P-1** 的直接教训）

★★ **`btc` 的期望行为（关键）**：契约 **C-1** 冻结 `btc` → **显式失败**（`code != 0`）。
故 btc 用例**期望的"成功" = 正确报错**，**不是**产生 bill。
执行者须把这一点写进断言，**不得**期望 btc 产生账单。

### (b) 桥的端到端（原报告 1.2）

起 Node + Go，**从 Node 侧**调 `reportResult` / `shouldCollect`，断言：
- 业务失败（`code != 0`）被识别为**失败**

★ **这正是 P0-3 逃逸的原因** —— e2e 直接打 Go API，**从未经过 Node 桥**。
★ 该断言同时是 `W2-C3` 修复的**回归保护**。

### (c) 负例矩阵（原报告 1.3）

| 负例 | 断言 |
|---|---|
| `amount` 为负 / 为 0 / 超精度 | **不留账单**，返回 `code != 0` |
| `settlement` 缺失 | `code != 0`（不得静默 0 账单 + code 0） |
| `token` 缺失 | 同上 |
| 并发同 `tx_hash` | 幂等：第二笔返回 `duplicated:true` 或 1062 回滚，**bill 不翻倍** |
| `chain` 为词表外值 | `code != 0` |
| `to_address` 与 settlement 不符 | ★ 当前**无此校验**（原报告 P1-5，**本轮未复核**）⇒ **本卡只断言并登记现状**，不要求通过 |

### (d) 纳入回归清单（原报告 1.4）

写入调度《机械门禁清单》（见《开发规则与调度说明》§九）。

## ★ 判据的前置断言（P-5）

脚本自身必须先证明「量尺有效」：
- 跑之前先确认三链的 settlement/token **确实已种入**
  （否则"0 条 bill"可能是**没数据**，不是缺陷）
- ★ **命中为 0 时先怀疑模式/数据，不是结论**

## 不在范围

- 不做真机 / 真链广播（`V0` 裁决 **D-4**）
- 不修任何缺陷（修复在 `F1-C*` 各卡）

## 证据要求

- `verify_money_path.py` 的真实退出码
- ★ **三链各自的真实输出**（证明没有只跑 `eth`）
- 负例矩阵**逐条**的真实结果
- 覆盖率声明：哪些路径**未**覆盖
