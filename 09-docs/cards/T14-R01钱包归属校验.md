## ★★★ 规格（**Owner 裁决 2：修**）

### ★ 修法的**正确方向**

**不是"拒绝 `wallet_id` 单独"**（**违反 C-2**），
**而是**：
**「**只要提供了** `device_id` ⇒ **它必须**与 `wallet_id` 指向同一 machine」**

### 语义对照

| 场景 | 现状 | **改后** |
|---|---|---|
| 三参数全有 | ✅ 校验（**`device_id` + `address`**）| ✅ 不变 |
| **`wallet_id` + `device_id`（无 `address`）** | 🔴 放行 | ★ **校验 `device_id` 归属** |
| **`wallet_id` + `address`（无 `device_id`）** | 🔴 放行 | ★ **校验 `address` 归属** |
| **`wallet_id` 单独** | 🔴 放行 | ✅ **仍放行**（**C-2 允许**）|
| `wallet_id` + 两者 | ✅ 校验 | ✅ 不变 |

### ★★ 实现要点

1. ★ **放宽触发条件**：**从「`deviceId != "" && address != ""`」改为「`deviceId != "" || address != ""`」**
2. ★ **按提供了哪个字段，构造对应的 WHERE 条件**：
   - 有 `device_id` ⇒ `AND machine.device_id = ?`
   - 有 `address`（且有 `chain`）⇒ `AND wallet.<col> = ?`
   - **两者都有** ⇒ **两者都加**（**与现状等价**）
3. ★★ **`address` 缺 `chain` 的处理**：
   - **若只提供 `address` 而无 `chain`** ⇒ **无法确定 `col`** ⇒
     ★ **停下报告**（**这是卡未预见的情况**）
4. ★★ **`device_id` 缺 `chain` 时仍可校验**（**`machine.device_id` 与 chain 无关**）

★ **保留 `:42-44` 的"缺省语义必须保留"注释精神**：
**`wallet_id` 单独仍放行**（**C-2 允许**），
**但"提供了 device_id/address 就必须一致"。**
