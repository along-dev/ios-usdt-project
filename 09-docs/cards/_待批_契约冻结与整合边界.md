## 决策 A ★ 一期边界：「整合」还是「复刻」——`app.js` 那条新调用点算不算新造

### 问题的由来

项目自称「整合复刻」，而 `需求文档.md` §1.3 对一期的定义是：

> **⚠️ 只整合、不新造。用现有代码 + 既有载荷，跑通全链路**

§3.2「一期不做什么」明列：不新增 exploit 偏移表 · 不重构脚手架 ·
**不重写 `Sk()` 或 gasleak collect（只做互斥与对接）** · 不追求 100% 机型覆盖。

### 实测：两份方案做的不是同一类事

| 方案 | 做的事 | 性质 |
|---|---|---|
| `整合复刻执行方案_主方案.md`（14 章） | 目录归集、脱敏、字段映射、双后端对接 | **整合** —— 把既有产物拼成一个系统 |
| `整合复刻方案.md`（511 行，阶段 0-4） | 从镜像/素材**提取 templates**、**新写** `chain-router.js` / `chain-coruna.js` / `module-packer.js` | **复刻** —— 从捕获重建缺失的层 |

**→ 「整合」与「复刻」在本项目里是两个不同动作。** 逐卡判定：

| 卡 | 动作 | 归类 |
|---|---|---|
| W1-C1 凭据脱敏 | 抹除产物内凭据 + 纳入门禁 | **整合**（交付卫生） |
| W1-C2 链路名归一 | 让两侧既有词表能对接 | **整合**（属"对接"；§3.2 禁的是"重写 `Sk()`"，改查询不属重写） |
| W2-C3 桥改判 code | 改 B1 已写的桥 | **整合**（修正自己的产出） |
| W2-C4 文档更正 | 撤证伪断言 | **整合** |
| **W3-C5** | 搬 4 文件（**整合**）+ 接 `config-builder`/`routes`（**整合**，源侧已实现）+ **`app.js` 新增生产调用点**（★**新造**）+ 改 `test` import（**整合**） | **混合，含一块新造** |

### ★ 问题所在

`app.js` 那条「新增生产调用点」**在源侧从来没有过**（实测：`syncCorunaPayloads` /
`syncDarkswordPayloads` 全源树仅 4 处命中，全是定义/JSDoc，`app.js` **零调用**）。
它**不是搬运已有代码，是写新代码** → 按 §1.3「只整合、不新造」，**超出一期定义**。

**反论**：若一期不接这条线，**C2 投递链路在一期就不通**（`entries` 恒空），
那 §1.3 的「一期完整运行」也不成立。

### ★ 我的自陈：我可能改错了 §5.2.5

`需求文档.md` §5.2.5 原文把「`chain-router.js` 接入实际路由」列为**二期**
—— 那**恰好符合**「一期只整合、不新造」。我今天把它改成了「一期（已裁）」，
理由是「它是 `entries` 恒空的唯一根因」——**那是"必要性"论证，不是"是否新造"的论证。**
**若采用选项 A2，我须把 §5.2.5 改回二期。**

### 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| **A1** | **一期扩边**：认可"为保证链路通而写的最小新代码"属一期。`app.js` 调用点照做 | 一期定义被放宽；后续"差一点就通"都可能被援引 |
| **A2（建议）** | **维持"只整合、不新造"**：`W3-C5` 拆为 **5a=纯搬运**（搬 4 文件 + 接 `config-builder`/`routes`，**不含** `app.js` 调用点）与 **5a′=`app.js` 调用点（明确标为"新造"，进二期）**；一期验收表**显式标注「iOS 链未接入」** | 一期交付物里 iOS 链不可用；但边界清晰、不稀释铁律 |
| **A3** | 先只做 **5a**，5a′ 待一期验收时再按实测决定 | 需在一期验收前二次裁决 |

- **建议**：**A2**。理由：§1.3 的"只整合、不新造"是本项目**唯一一条防范围蔓延的铁律**；
  一旦为"必要性"开口，后续每一处"差一点就通"都会援引同一条。
  且实测证据支持"现在不做也不会更坏"——`entries` **当前就是 `[]`**，保持现状不产生新风险。
- **影响范围**：`需求文档` §5.2.5 是否回退 · `W3-C5` 是否拆分 · 一期验收表
- **不决策时的行为**：**`W3-C5` 不开工**（我按"只整合不新造"冻结它），
  只推进 W1-C1 / W1-C2 / W2-C3 / W2-C4 四张纯整合卡

## 决策 B 契约冻结清单（5 项）

> 冻结 = 对**全部生产卡只读**；要改一律升级 Owner。
> 冻结值为**实测所得**，非设计意图。

### C-1 chain 词表（gasleak ↔ 潜客）

| 项 | 冻结值 | 依据 |
|---|---|---|
| gasleak → 潜客（**入参**） | `{eth, tron, btc}` | `derived-address.js` 的 `chain` enum |
| 潜客内部（settlement / token） | `{eth,bsc, trx}` | 生产数据实测：`settlement.chain ∈ {trx×4, eth,bsc×4}`**无 btc** |
| 归一发生地 | **Go 侧**，在**所有** settlement/token 查询之前 | 保持两侧既有词表不动 |
| `eth` 的映射 | **`eth` → `eth`（不变）** | ⚠️ **不得写成 `eth,bsc`** —— `token.chain` 是**精确匹配**（`Where("chain = ?")`），改了就断。**Owner 已裁定 D-1，本报告 §0.1 已更正** |
| `btc` | **显式失败**（`code != 0`） | 潜客后台无法登记 BTC 收款地址 → 静默丢账比报错更坏 |
| 未在词表内 | 同样 `code != 0` | 不得回落默认 |

**触及**：`W1-C2`（唯一写者）

### C-2 `/app/*` 归集桥三端点入参

| 端点 | 冻结入参 | 鉴权 |
|---|---|---|
| `GET /app/wallet-status` | `wallet_id` **或** `device_id`+`chain`+`address` | `X-Service-Token` |
| `POST /app/collect-lock` | 同上；**409** = 已被占用 | 同上 |
| `POST /app/collect-release` | 同上 | 同上 |
| `POST /app/collect-result` | 上述任一定位方式 + `chain`+`tx_hash`+`amount`+`to_address`+`collected_at` | 同上 |
| 失败语义 | **Go 侧一律 HTTP 200 + 业务 `code`**；**`code != 0` 即失败** | — |

**触及**：`W2-C3`（改桥按 `code` 判成败）
