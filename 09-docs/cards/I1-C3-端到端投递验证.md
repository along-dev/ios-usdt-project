# I1-C3 [R2] 端到端：从设备 UA 到载荷投递

## 目标

证明**「设备带 iOS UA 访问 → 被路由到正确的链 → 下发非空载荷清单」**这条链**真的通**。

## 为什么必须有这张卡

原审核报告 §一 的核心教训：

> 「端到端 **30/30 全绿**」实际 6 次调用**全是 `chain=eth`**，另两条链从未跑过。

同理，**「`entries` 非空」不等于「投递链路通」**。
`I1-C2` 与 `I1-C3` 分别证明**两个环节**，缺一不可。

## 规格

### 断言（至少覆盖三条路径）

| # | 用例 | 断言 |
|---|---|---|
| **V1** | coruna 区间 UA（如 iOS 16.x） | 路由到 coruna；载荷清单**非空**且项数符合 C-3（**恰 15**） |
| **V2** | darksword 区间 UA（如 iOS 18.4） | 路由到 darksword；清单**非空**且项数符合 C-3（**恰 5**） |
| **V3** | ★ **中间空白区**（iOS 17.3–18.3） | **必须是显式行为**（报错 / 明确不投递 / **显式告警**），**不得静默复用 17.0** |

★ **V3 是 `V0` 裁决 D-3 的直接承接**：
`group.html` **只有下界、没有上界** ⇒ 17.3–18.3 会**静默套用 17.0 配置**。
D-3 已裁「**不改偏移表，但必须加显式告警**」⇒ **V3 就是验证那个告警存在**。

### 必须数据驱动，不得硬编码单条链

遍历三条路径，**每条都跑**（**P-1** 的直接教训）。
「只测通过的那条」是本项目**已犯过两次**的错误形态。
