# `W1-C15` [R3] **遗留表收敛到一处**（消掉「遗留层内部重复」）

## 目标（一句话）

把 `build_unified.ps1` 与 `sanitize_target.ps1` **各写一份**的 8 条遗留表（`$SANITIZE_LEGACY_REPLACEMENTS` ／ `$LEGACY`），
**收敛到<ins>一份</ins>产物外的登记件** ⇒ 消掉「同一份清单两处各写、各自漂移」的风险。

## ★★ 红线：**不得把遗留层并进「集外凭据登记层」**

**遗留层** 与 **集外凭据层** **语义不同** —— 这正是 `W1-C14` A 组 `BLOCKED` 的成因（`L074`／`L078`）：

| 层 | 内容 |
|---|---|
| **遗留层** | 与 `build_unified.ps1` 同源的**遗留值／派生前缀**（**8 条**；`L078 §2` 实测：**遗留 8 · 派生 0 · 真集外 0**） |
| **集外凭据层** | `extra_credentials.json`（**3 条**），**只装集外** |

⇒ ⛔ **本卡<ins>不改</ins> `extra_credentials.json`**（**只读**）；⛔ **不得把两者合并**。
⇒ ★ **本卡的目标是「遗留表只写一份」，<ins>不是</ins>「并进登记层」** —— 请勿读成后者。

## 规格（可判定）

1. ★ **收口方向<ins>写死</ins>：选「两者共读一份<ins>产物外</ins>的遗留登记件」**（Owner 给的两选一之一；**理由见下节**）。
   **新建** `E:\ios漏洞\_integration\_fix_work\legacy_replacement_patterns.json`（**产物外**，⛔ 绝不复制进产物）。
   结构：**有序数组** `[{"value": "<值>", "placeholder": "<占位符>"}, …]`，**8 条**。
2. **两侧都改为从该件读**：`build_unified.ps1` 的 `$SANITIZE_LEGACY_REPLACEMENTS` 与
   `sanitize_target.ps1` 的 `$LEGACY` **均不再内嵌字面表**，改为读该件。
3. ⛔ **不得改变对外行为**：替换**结果逐条不变**（演练 `替换项` 仍为 **`93`**）；`-Apply`／演练语义不变；
   `sanitize_target.ps1` 的 `$BackupDir` 行为不变；**两侧仍按「长度降序」消费**（见 verify ③）。
4. ⛔ **不得把任何凭据**值**写进产物内文件**；该登记件**不得进产物**；需要指称时只写「**位数 ＋ 指纹**」。
5. **派生层不动**：`_secrethunt\assets.json` **只读**；`extra_credentials.json` **只读**。
6. **不改** `acceptance_final.ps1`／`verify_redaction_reverse.py`／`verify_w1c1_credentials.py`；
   **不改产物**；**不改** `_manifest.sha256`；**不改契约本**。

## ★ 为何选「共读一份产物外登记件」而不是「`sanitize_target` 从 build 读」

| # | 理由（**均已现读核实**） |
|---|---|
| **1** | **「从 build 读」做不到"只写一份"而不引入新机制**：build 的表**内嵌在脚本体内**（`:174-184`），而该脚本有 `param(...)`（`:8` `$Target` Mandatory）⇒ 要读它只能 **(a) 解析脚本文本**（脆弱，**正是本次要消除的那类**）或 **(b) dot-source**（会连带执行其主体）。⇒ 该路**要么引入解析依赖、要么改 build 的暴露面**。 |
| **2** | **沿本项目已立的<ins>同一手法</ins>**：`W1-C10` 建的 `extra_credentials.json` 就是「**产物外一份、多方共读**」（**四读取方**）⇒ 本卡是**同一手法的第二次应用**，不新造概念。 |
| **3** | ★★ **它顺带把一条<ins>隐藏陷阱</ins>显式化**（**若不写清，执行者极易改错而集合比对看不出来**）：两处的**替换顺序<ins>都不是</ins>由字面表序决定** —— `build_unified.ps1:370-373` 与 `sanitize_target.ps1:57／:97` **都按「长度降序」重排**（`Sort-Object -Property Length -Descending`）。⇒ 收敛时**必须写明这一点**，⛔ **不得**让"登记件的字面顺序"被当成语义（那会**静默改行为**）。 |

## 证据要求

- ★ **两处消费面<ins>逐条相同</ins>**：`chk_legacy_subset.py` 输出（**双向差集 = 0**）
- ★★ **"只写一份"的实测**：登记件**加一条哨兵**（自编假值、≥12 字符）⇒ **两侧同时出现**；**删哨兵** ⇒ **两侧同时消失**；
  并贴 **检索 = 0** ＋ **登记件条目数复位 = 8** 的证据
- ★ **顺序断言**：两侧**有序清单**各贴一份（位数 ＋ 指纹）＋ 说明两侧均为**长度降序**
- ★ **行为逐条不变**：演练 `替换项 = 93` ／ `DRY_EXIT=0` ／ 目标目录**零写入**
- ★ 回归：`acceptance_final.ps1 -Target E:\USDT项目` 与 `verify_redaction_reverse.py -Target E:/USDT项目` 的真实退出码（**均须 0**）
- 三件的**改前／改后 sha256 ＋ bytes**（含**新建件**）
- ★ 声明：**产物一个字节未动**；**该登记件未进产物**（贴检索 = 0）
- 保真：两个 `.ps1` 的 BOM 前三字节（hex）＋ `Parser::ParseFile()`；`.json` 的 UTF-8 无 BOM ＋ 条目数
- **输入锚**：每条断言**跑前/跑后**被改件的 sha256（**须同值**）
