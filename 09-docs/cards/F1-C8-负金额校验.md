# F1-C8 [R3] 负金额/零金额可落账 —— 资金写入路径缺校验

## 目标

让 `amount <= 0` 的归集回传**被显式拒绝**（`code != 0`），**不产生任何 bill**。

## 缺陷事实（★ 由 I2-C1 真 HTTP + 真 DB 实测发现，非静态推断）

**复现（实测）**：

```
POST /app/collect-result
  X-Service-Token: <app-jwt.service-token>
  {"chain":"tron","tx_hash":"i2c1-neg-proof","amount":"-5","wallet_id":1,"collected_at":...}

响应: HTTP 200 {"code":0,"data":{"billId":383,"duplicated":false},"msg":"ok"}

DB 落账（qk_e2e.bill）:
  role  num     total_num  usdt_num
  1     -0.5    -5         -0.5      ← 平台"负收益"
  2     -3.5    -5         -3.5      ← 客户"负收益"
  3     -1      -5         -1        ← 代理"负佣金"
```

**根因**：`collect_result.go:92-95` 只校验「能否解析为 decimal」，
**未校验正负号**：

```go
totalAmount, e := decimal.NewFromString(req.Amount)
if e != nil {
    return fmt.Errorf("invalid amount %q: %w", req.Amount, e)
}
// ← 此处无 IsNegative() / IsZero() 校验
```

**危害**：
- 负 `amount` 会**反向冲减**代理/客户 `usdt_num`；
- 归集回传是**唯一能污染分账数据的写入口**（`collect_result.go:59-60` 自身注释）；
- 一旦 gasleak 侧被投毒或算错，可直接**抹掉代理/客户账面收益**。

**对照**：`scan.go` 的 `Sk()` 在私域分支有 `!decPrivate.IsZero()` 保护，
公域分支亦经 `mkBill` 的 `num.IsZero()` 兜底 —— 但**负值两侧都无保护**。

**`amount = 0`**：`code=0` 但 0 笔落账（`mkBill` 的 `num.IsZero() → nil` 兜底）。
虽不产生坏数据，但**回 ok 是误导**（调用方会以为已记账）⇒ 一并显式为错。

## 规格

### (a) 在 amount 解析后加显式校验

```go
totalAmount, e := decimal.NewFromString(req.Amount)
if e != nil {
    return fmt.Errorf("invalid amount %q: %w", req.Amount, e)
}
// ★ F1-C8：金额必须为正。负值会反向冲减代理/客户账；零值回 ok 会误导调用方。
if totalAmount.IsNegative() || totalAmount.IsZero() {
    return fmt.Errorf("invalid amount %q: must be positive", req.Amount)
}
```

### (b) 不得改动既有口径

- `mkBill` 闭包**不动**；
- 公域三笔 / 私域单笔（role=4）的金额算法**不动**；
- 比例计算（技术服务费 / 代理 ratio / 客户残差）**不动**。

### (c) 不得改 `scan.go`

它是口径基准，且其 `Sk()` 有各自的零值保护。**本卡只读它**。
