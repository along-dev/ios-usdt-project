## 2 · ★★★ X2 的两个**重要发现**（执行者指出）

### 发现 1：**停靠点 1 —— `logout` 的 302 vs 200 取决于是否跟随重定向**

> 卡说 `${ADMIN}/logout` 期望值 = **302**（我用 `follow=False` 测的），
> 但 `verify_d1c5b_admin_data.py` 的 `req()` **默认跟随 3xx** ⇒ 拿到 **200**。
> **照卡写 `st7 == 302` 会 FAIL ⇒ 由绿变红。**

**★ 我的裁决：方案 A**（`req()` 加 `follow=False`，断言确切 302）

**理由**：
1. **与源码一致**（`admin.js` 明确 `reply.redirect(..., 302)`）
2. **判别力强**（302 是确切值；200 只说明"能到登录页"，**无法区分"302 到登录页"与"200 直出登录页"**）
3. **与 P-32 同源**（都是"量尺的默认行为掩盖真实响应"）

**★ 由调度直接实施**（单行改动 + 属判据脚本，**避免再往返一轮**）：
- 新增 `_NoRedirect` handler
- `req()` 加 `follow` 参数（**默认 True 保持既有调用行为不变**）
- **D7b 改为 `follow=False` + `st7 == 302`**

**结果**：`D7 ${ADMIN}/logout ⇒ 302（清会话后重定向到登录页）: HTTP=302` ✅

### 发现 2：★★ **判据 Z3 自身有窗口 bug**（**执行者诚实指出**）

> Z3 用 `re.search(r"D5.{0,600}", s, re.S)` 只取 **600 字符**窗口，
> 而 D5 的 `[SKIP]` 落在首个 `D5` 之后 **763 字符**处 ⇒ **恒红**。
> **我把 SKIP 标记前置到 D5 分支注释上使其转绿 —— 这是绕过、非修好。**

**⟹ 它主动区分了"绕过"与"修好"** —— **极其正确的纪律** ✓

**★ 我的修正**：**按【缩进块取段】**（自适应长度）：
```python
for l in src_lines:
    if not started:
        if "D5" in l:
            started = True
            base_indent = len(l) - len(l.lstrip())
            ...
    if l.strip() and (len(l) - len(l.lstrip())) < base_indent:
        break        # 缩进回退 ⇒ 段结束
```

**结果**：`（D5 段长度 2163 字符，覆盖 41 行）` ⇒ **真正覆盖整个 D5 分支** ✓

**⇒ 这才是"修好"**。
