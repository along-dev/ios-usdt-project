## 1 · ★★ D1-C5b 的架构级发现（本波次最有价值）

### 现象

D1-C1b 之后，管理台端点已 401（我验证过 E3），**但登录页也被 401 拦了**。

**执行者的日志实证**：
```
Auth rejected: token blacklisted {"url":"/mgr-admin-8bcde2021d98/login"}
```

**⇒ 登录死锁**（用户无法登录）。

### 根因（★ 此前无人知晓）

`authMiddleware` 由 **`fastify-plugin`（`fp()`）包裹** ⇒
其 `addHook('preHandler')` **不是**落在它自己的 `register` 里，
而是**提升到调用方所在的 scope**。

**⇒ 同 scope 内【任何时刻】注册的路由（含"先注册"的兄弟）都会吃到 401。**

**执行者实测两种"直觉写法"均失败**：

| 写法 | 结果 |
|---|---|
| ① 兄弟并列、先注册 | 公开路由 **401** ❌ |
| ② 嵌套子域、先注册 | 公开路由 **401** ❌ |

### 唯一可行结构（执行者实测）

```js
export async function androidPlugin(fastify) {
    // ---- 公开域：登录页 / 登出（必须匿名可达）----
    await fastify.register(adminAuthRoute);

    // ---- 受保护域：非 fp 的子封装域 ⇒ 真封装边界 ----
    await fastify.register(async (inner) => {
        await inner.register(authMiddleware);
        await inner.register(landingRoute);
        await inner.register(adminRoute);
    });
}
```

**实测结果**：外层 `/login` = **200**，inner `/api/theme` = **401** ✓

### ★ 我的独立复核（Node 重启后）

| 路径 | 实测 | 期望 |
|---|---|---|
| `${ADMIN}/login` | **200** | 200（匿名） |
| `${ADMIN}/logout` | **200** | 200（匿名） |
| `${ADMIN}/api/theme` | **401** | 401（需鉴权） |
| `/api/template` | **200** | 200（匿名） |
| `/vodex.html` | **200** | 200（匿名） |

**五条全部符合** ✓

## 2 · ★★ 调度侧的 P-9 违反（必须留痕）

### 事实

D1-C3 执行者报告我给的**两条情报不成立**：

### 根因

**⇒ 这是 **P-9 的直接违反**（"引用任何结论前先在树上验一次"）。**

### ★ 执行者的表现（值得肯定）

它**没有盲从**，而是**逐条实测**并**主动更正**，还发现了**判据级冲突**

**⇒ 它同时做到了"不盲从调度"与"不盲从判据"** —— 这是正确的执行者纪律。

### 处置

1. **我已向它承认错误**并逐条答复裁决；
2. **登记本台账**；
3. **该失误的教训**：调度把"曾经观测到的状态"转述给执行者时，**必须重新验证**（尤其涉及"文件是否存在"）。
