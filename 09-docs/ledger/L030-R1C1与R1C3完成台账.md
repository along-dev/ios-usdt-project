## 2 · ★★ R1-C3（`verify_f1c5_runtime.mjs` 模块解析修正）

### 缺陷与根因（**调度先前已实证**）

| 跑法 | 结果 |
|---|---|
| **从 `_fix_work`** | ❌ `ERR_MODULE_NOT_FOUND: Cannot find package 'fastify'` |
| **从 `02-backend-node`（副本）** | ✅ **输出路由表** |

**根因**：**ESM 从【脚本所在目录】向上找 `node_modules`**；脚本在 `_fix_work` ⇒ 找不到。

### ★ 三个方案的实证（**调度做**）

| 方案 | 结果 |
|---|---|
| **(a) 移入产物目录** | ⚠️ 会给产物加文件（**与源卡 verify 冲突**）|
| **(b) 改导入方式** | ✅ **可行**（见下）|
| **(c) 软链** | ❌ **不可行**（Junction / mklink / subst **全 `Incorrect function`**）|

**方案 (b) 的三种导入方式**：
| 方式 | 结果 |
|---|---|
| 裸绝对路径 `E:/...` | ❌ `ERR_UNSUPPORTED_ESM_URL_SCHEME` |
| **`pathToFileURL(...)`** | ✅ |
| **`createRequire(产物 package.json)`** | ✅ **（推荐）** |

### 产出

| 项 | 值 |
|---|---|
| **脚本** | `_fix_work/verify_f1c5_runtime.mjs` |
| **改前** | `07413273435e598c…` / **4,620 B** |
| **改后** | **`513b859f4b9895fb…` / 5,170 B** |
| **改动范围** | **仅导入部分**（**T1–T7 断言区一字未动**，+550 B 全为注释与导入）|

**采用的实现**（**方案 (b) + 方式 3**）：
```js
import { pathToFileURL } from 'node:url';
import { createRequire } from 'node:module';

const REPO = 'E:/USDT项目/02-backend-node';
const req = createRequire(`${REPO}/package.json`);
const Fastify = req('fastify');
const { landingRoute } = await import(
    pathToFileURL(req.resolve('./src_restored/plugins/api/routes/landing.js')).href
);
```

★ **以产物 `package.json` 为唯一基准，完全不依赖脚本自身位置** ✓

> (c) 卡已证伪；方式 1 裸 `E:/` 路径会 `ERR_UNSUPPORTED_ESM_URL_SCHEME`，
