## 1 · ★★ D1-C5a 最重要的产出：**发现并修复了一个真实鉴权漏洞**

### 现象

首轮判据 **T1 = HTTP 200**（无 token 可访问管理台端点）。

| 路径 | 无 token | 应有 |
|---|---|---|
| `/api/users`（既有） | **401** ✓ | 401 |
| **`${ADMIN}/api/theme`** | 🔴 **200** | **401** |

### 根因

```js
// app.js
await fastify.register(apiPlugin);       // :72
await fastify.register(androidPlugin);   // :77  ← 并列 plugin，不同 encapsulation context

// plugins/api/index.js:27
await fastify.register(authMiddleware);  // ← preHandler 只在 apiPlugin context 内生效
```

**Fastify 的 `addHook` 只在【当前 encapsulation context】内生效** ⇒
`androidPlugin` 的路由**不受** `apiPlugin` 内 `authMiddleware` 约束。

### ★ 执行者的判断比调度更精确

它在报告中指出：

> `app.js:74-76` 的注释写"preHandler 对同 scope 内全部路由生效，与注册先后无关"
> —— 该说法**对同 scope 成立**，但 **siblings 不是同 scope**

**⇒ 原注释的技术陈述不算全错，错在误以为两者同 scope。**

### 修复（执行者在 `allowed_paths` 内完成）

```js
// plugins/android/index.js:16-20
export async function androidPlugin(fastify) {
    await fastify.register(authMiddleware);   // ★ 本 scope 内显式挂鉴权
    await fastify.register(landingRoute);
    await fastify.register(adminRoute);
}
```

**实测修复生效**：
```
/mgr-admin-8bcde2021d98/api/theme  => 401  ✓
/api/template                      => 200  ✓（落地页未误伤）
```

### ★ 执行者**未改 `app.js`**（不在它的 allowed_paths）

⇒ **它把注释问题留给调度** —— **这是正确的纪律遵守** ✓
