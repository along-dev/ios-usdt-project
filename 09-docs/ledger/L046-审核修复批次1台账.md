## 3 · 逐项详情

### 3.1 A-B1：代理代签（**我引入的安全漏洞**）

**审核 A 的交叉验证**：
| 实验 | 结果 |
|---|---|

| **T3** 经代理**无凭证** | 🔴🔴 **200 + 业务数据** |

**⇒ 证明是【服务端代签】。**

**修法**：**删除 `nodeToken()` 注入** ⇒ **纯透传** ✓

### 3.2 C-1：管理台 RBAC

**根因**（`auth.js:68-72`）：
```js
const matchedKeys = findMenuKeyByPath(urlPath);
if (matchedKeys.length === 0) return;      ← ★ /mgr-admin-* 返回空数组 ⇒ 放行
```

**修法**：**加管理台闸，用 `isSuperAdmin`**（**不含 `channel_admin`**）✓

**★ 关键判断**：**`isAdminLike` 含 `channel_admin`** ⇒ **Owner 裁决「只允许 admin」⇒ 必须用 `isSuperAdmin`**。

### 3.3 C-13：C2 控制面

**★★ 关键取证**：**载荷侧无任何凭证机制**
- **`05-ios` 全树搜 `x-ts`/`AES_KEY_PREFIX`/加密调用 ⇒ 零命中**
- **`06-android` 含 c2 端点的文件 ⇒ 0**

**⇒ **不能套 `authMiddleware`**（**会断载荷链**）。**

**修法**：**新增 `plugins/c2/guard.js`**（**限频 + body + 审计 + 白名单**）
+ **`taskresult` 归属校验** ✓

**★ 验证**：
| 判据 | 结果 |
|---|---|
| **限频** `/taskget` | ✅ **前 9 次 200 ⇒ 后 5 次 429** |
| **body 限制** | ✅ **1.2MB ⇒ 413** |
| **★ 载荷链未断** | ✅ **7 端点全 200** |

### 3.4 C-5：命令注入

**根因**：`applications.js` 的 6 处 `execSync` 用 shell 反引号拼接，且 `channel` 未净化。

**修法**：
- **加 `assertSafeChannelToken()`**（**仅 `[A-Za-z0-9_-]`**）
- **`execSync` → `execFileSync`**（**参数化**）
- **`cp/rm` → `cpSync`/`rmSync`**（**无 shell**）

**★ 验证**：**14 恶意全拒 / 5 合法全过 / 0 误伤** ✓
