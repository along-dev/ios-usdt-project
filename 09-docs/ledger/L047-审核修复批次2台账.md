### 1.2 本轮实测发现并修复的**两个 panic**

#### ★ panic #1：`authorities_menus.go:47` 切片越界

```
panic: runtime error: slice bounds out of range [:20] with capacity 13
  at source/system/authorities_menus.go:47
```

**根因**：上游实现**硬编码切片下标**——
```go
menus[:20] / menus[21:] / menus[:12] / menus[13:17]
authorities[0] / authorities[1] / authorities[2]
```
隐含「菜单恰有 ≥22 个、角色恰有 3 个」。

**修复**：改为**边界安全**的 `safeSlice` / `at` 辅助函数；
不足时**按实际长度降级**（**语义不变，只是不越界**）。

#### ★ panic #2：`core/server.go:32` 业务表未迁移

```
Error 1146: Table 'qk_t26_empty.token' doesn't exist
  at blockchain/scan.go:17
  at core/server.go:32 → panic(err)
```

**根因**：`LoadRpcList()` 在 `token` 表不存在时报错，而**任何 error 都 panic**。

**修复**（两处）：
1. **`core/server.go`**：`panic(err)` → **`global.GVA_LOG.Warn(...)`**（**降级，不阻断**）
2. **`initialize/gorm.go`**：把 **10 个业务 model** 纳入 `AutoMigrate`

★ **类型名取自实读**（`model/app/*.go` 的 10 个 struct）：
`Agent` `BatchBill` `Bill` `Custom` `Machine` `Packet` `Settlement` `Token` `Wallet` `WalletBalance`

#### ★ panic #3（编译期）：`errors.Wrap` 未定义

```
service\system\sys_initdb.go:115:17: undefined: errors.Wrap
```

**根因**：`sys_initdb.go` import 的是**标准库 `errors`**，而 `errors.Wrap` 属 `pkg/errors`。
**修复**：改用 **`fmt.Errorf(..., %w)`**。

### ★★ `verify_t21_previews.py` 的**判据自身 bug**（本轮发现并修复）

**现象**：`V2 GET vodex.png -> 200 CT='' bytes=4257` —— **status/bytes 都对，只有 `Content-Type` 读为空**。

**取证（决定性）**：
```python
r.headers.get('Content-Type')       = 'image/png'   ✅
dict(r.headers).get('Content-Type') = None          ❌ ← 脚本走的路径
dict(r.headers).get('content-type') = 'image/png'   ✅
```

**根因**：`http()` 返回 `dict(r.headers)`，**`dict()` 转换丢失 HTTP 头的大小写不敏感性**
（键变成服务端发出的原始大小写 = 全小写 `content-type`），
而调用处用**驼峰 `"Content-Type"`** 取 ⇒ **恒为 `None`** ⇒ **把正常响应误判为 FAIL**。

**★★ 服务完全正常**（**raw socket 实测返回 `content-type: image/png`**）。

**修复**：新增 `_CIHeaders`（**大小写不敏感的映射包装**），保持调用方签名不变。

**★ 同族教训**：**判据 bug 会伪装成产品缺陷** —— 这是自审核以来的第 **16** 次纠正。
