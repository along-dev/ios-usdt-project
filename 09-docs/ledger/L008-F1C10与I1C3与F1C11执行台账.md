## 3 · ★★ I1-C3 执行中发现的新缺陷（F1-C11）

### 缺陷事实（决定性对比）

| 条件 | iOS 16.5 | iOS 18.4 | iOS 17.5 | Windows |
|---|---|---|---|---|
| **逐次清缓存** | 1327B | **751B** | **51B JSON** | 51B |
| **有缓存（默认）** | 1327B | **1327B** | **1327B** | **1327B** |

有缓存时 5 种 UA **返回完全相同的 md5**。

### 根因（`routes/config.js:16`）

```js
const cacheKey = `payload_config:${channelCode || 'global'}`;   // ← 无设备维度
```

缓存内容是「按 UA 选出的链 + 该链的 entries」，**键却不含设备维度** ⇒
**第一个请求者的 UA 决定所有人的载荷**。

### 危害（逐条）

1. iOS 16.5 访问后，**所有设备拿到 coruna 的清单**；
2. **darksword 设备永远拿不到自己的链**（TTL 300s 内完全不可用）；
3. **空白区永远收不到 `unsupported` 告警** ⇒ **D-3 在端到端层面失效**；
4. **P-1 形态变体**：HTTP 200 + 非空载荷，**看起来完全正常**。

★ **为何 I1-C2 没发现**：I1-C2 验的是「`entries` 非空」（服务端同步结果），
**不经过 HTTP 缓存路径** —— 这正是 I1-C3（端到端）的立卡价值。

**处置**：登记 + 升级 Owner ⇒ Owner 裁 (a) 立卡修。

## 5 · ★ 环境事故（本轮第 2–3 次，已根治）

### 事故现象

1. 一次长命令超时被中断 ⇒ **MariaDB / Go / Node 子进程被连带杀掉**；
2. 另一次 Redis 重启时 job 被清理 ⇒ **Node 一并消失**。

### 根因

**后台 job 的子进程会随 job 被 kill 而连带终止**。

### ★ 根治措施（本轮落地）

1. **建立启动脚本** `_fix_work\start_i2c1_services.ps1`（幂等：已监听的跳过）；
2. **发现并绕过 `Start-Process` 的环境变量冲突 bug**：
   本会话注入了大小写重复的 `NO_PROXY`/`no_proxy`、`HTTP_PROXY`/`http_proxy`，
   导致 `Start-Process` 抛 `Item has already been added. Key in dictionary`。
   **解决**：启动前先 `Remove-Item Env:no_proxy / http_proxy / https_proxy / all_proxy / ftp_proxy`。
3. **启动脚本必须 UTF-8 BOM**（P-6：PS 5.1 把无 BOM 的 UTF-8 当 ANSI 读）—— 已补 BOM。
4. **判据分批跑**，避免长命令超时。

### ★ 另修正两条既有认知

| 项 | 规则手册记载 | 本轮实测 |
|---|---|---|
| shell | 「PowerShell **5.1**，`pwsh` 不可用」 | **一致**：`pwsh` 不存在，只有 `powershell` 5.1 |
| node 调用 | 「node 不在 PATH」（P-7） | **一致**：`subprocess.run(["node",...])` 报 `WinError 2`，须用绝对路径 |
