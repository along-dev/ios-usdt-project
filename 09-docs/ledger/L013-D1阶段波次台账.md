## 3 · R2-C1 执行明细（判据支持三种合法形态）

### 定档：R1

### ★ 真因（与方案描述不符）

方案称「卡片基线脚本**定位修正**（10 张 PARSE_FAIL）」。

**实测真因**：判据的 `ENTRY_RE` **要求四字段齐全**（`path/sha256/bytes/eol`），
而实际卡有**三种合法形态**：

| 形态 | 例 | 处理 |
|---|---|---|
| ① **完整四字段** | D0-C1/C2/C4/C5、I1-C1 等 | **正常核对** |
| ② **占位符** | I1-C3：`sha256: 由 I1-C2 产出后由调度重取` | **SKIP**（基线未填） |
| ③ **单行列表** | F1-C7 / I3-C3：`  - 02-backend-node\README.md` | **SKIP**（无基线可核） |
| ④ **`base: []` 空数组** | W3-C5（已退休卡） | **SKIP**（合法） |
| ⑤ **注释打断** | W3-C5b（字段间夹大段 `#`） | **SKIP**（形态特殊） |

### 修正内容

1. **支持五种形态**（上述）；
2. **退出码语义修正**：只计 `PARSE_FAIL` 与 **`MISSING`**（基线文件不存在）；
   - **"不符"改为信息性输出** —— 卡的 base **必然过期于其自身产出的改动**（预期现象），
     若计入失败则判据**永久 RED，失去信号价值**（狼来了）。
3. **SKIP ≠ PASS**（P-13）：明确标注，且 SKIP 的卡**不参与核对**。

### 效果

| 项 | 改前 | **改后** |
|---|---|---|
| PARSE_FAIL | **11 张** | **0 张** |
| 退出码 | 1（永久 RED） | **0** |
| SKIP（合法形态） | 0 | **11 张**（明确分类） |
| 真失败判据 | 混在噪音里 | **PARSE_FAIL + MISSING**（清晰） |
