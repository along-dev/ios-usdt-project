## 2 · ★★★★ 本轮最重要的发现：**cookie 折叠 bug**（X6b 执行者发现）

### 它的诊断

> **根因**：判据的 `http()` 返回 `dict(r.headers)`，**折叠重名响应头**。
> `Set-Cookie` 有 **accessToken + refreshToken 两条**，转 dict 后 `h.get('Set-Cookie')` **恒为空**
> ⇒ `login_token()` 永远返回 `None` ⇒ **Y2/Y3/Y6 被 SKIP**，
> 且 **Y4 的跟随请求裸发、不带任何 cookie** ⇒ **必然 401**。
> **⇒ 我第一版实现后判据仍 RED（3/4）——那是假红，与被测路由无关。**

### ★ 影响面（它主动警告）

> 此 bug 会让**任何依赖 cookie 鉴权的判据**假红或静默 SKIP，
> 建议**同步排查 X6 等同族脚本**。

### ★ 我的处置

1. **修正 X6**（同一 bug）：
   - 新增 `_hdrs()`（用 `get_all("Set-Cookie")` 取全量）
   - 新增 `set_cookie_text()`（全量拼接供正则提取）
   - **W2b 跟随 302 时带上 cookie**
2. **全量排查 57 个判据脚本**：

| 状态 | 数量 |
|---|---|
| **★ 仍折叠重名头** | **0** ✓ |
| ✓ 已正确处理 | **6** |

**⇒ 无残留** ✓

### ★ X6 修正后的结果

```
W2  表单登录 ⇒ 302 + cookie（Set-Cookie 条数=2）   ✅
W2b 带 cookie 跟随 ⇒ 200                            ✅
= 9/9 GREEN
```

**⟹ 一个量尺 bug 的修正，让 X6 从"假红"变成"真绿"，**同时暴露并修复了一个真实缺陷（dashboard）**。**
