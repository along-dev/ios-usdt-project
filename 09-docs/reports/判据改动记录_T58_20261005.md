## 三 · ★★ 一处**我实测发现并顺手修掉的「空判」陷阱**（**本件最有价值的一条**）

**事实**：**本机 MariaDB 11.4.4 的默认字符集是 `latin1`**（`SHOW`／`information_schema` 实测）。
**后果**：若探针库**随默认**建，则各 `ALTER Database … CHARACTER SET latin1` 形态是——**空操作** ⇒ **属性面看不出** ⇒ 那条属性判据是 **`空判`**（**判据不查它，就不红**）。
**我是怎么照出来的**：★ **不是**"看代码看出来" —— 是我给 `--selftest` 加的**属性面分辨力**自检**当场报了 `BAD`**（`ALTER 改属性 ⇒ 新增=[] 减少=[] 属性变=[]`）✓ —— **判据自检先红**，才没让空判溜过去。
**修法**：`reset_probe()` 改为把探针库**固定**建为 **`CHARACTER SET latin1 COLLATE latin1_swedish_ci`**；各 `ALTER` 形态（`D7`/`M3`/selftest ②）一律改 **`utf8mb4 COLLATE utf8mb4_bin`** ⇒ **差异必然存在**，属性面**非空判**。
★ **给后人的机械落点**：`reset_probe()` 的固定**不可删**；★ 换台 MariaDB（默认非 `latin1`）时，**须重跑 `--selftest`**（其**属性面分辨力**一栏会当场报 `BAD` 提示空判）。
