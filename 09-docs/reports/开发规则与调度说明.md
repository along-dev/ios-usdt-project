# 开发规则与调度说明

> **文档定位**：本文件把项目**已在运行的开发规则**整理成一份可直接交给调度与开发者的说明。
> **来源**：`09-docs/cards/_总调度启动提示词.md`（规则主体）+ 本轮审核实测补充。
> **性质**：本文件是**规则说明**，不是新规则发明者 —— 未在既有材料中出现的条目，均标注「★ 本轮新增建议」。

---

## 一、一句话总纲

**写的人不审，审的人不改，派发的人不写代码。**

这是元规则。它决定了本项目的一切组织形态：
- 调度**不写实现代码**，只做**派发、复核、裁决、汇报**；
- 审核者看到的副本与执行者**不是同一份**，且**两路审核者之间也不共享副本**；
- 契约本由 Owner 冻结，**任何角色不得自行修订**。

---

## 二、角色与权责

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **Owner** | 裁决契约、裁决停靠点、批准 P0/P1 处置 | 不直接改代码 |
| **总调度** | 派发、复核 verify、裁决分歧、写台账 | **不写实现代码** |
| **执行者** | 按卡实现 + 自报 verify 退出码 | 不改卡外文件、不自行扩大范围 |
| **审核者** | 独立复核（R1 一名 / R2 两名异质 / R3 加专项） | **不改任何文件** |

### 门禁形态：为什么不是「四 SHA」

**本项目无 git**（`E:\USDT项目`、`E:\ios漏洞`、`E:\ios漏洞\_integration` 均非 git 仓库）。

⇒ 因此：
- **不建分支、不建工作树**，卡片 `task_branch` 一律写「无」；
- 一致性核对改用 **「内容 sha256 地基」**：逐文件 `sha256 + bytes + eol` 记入卡片 `base`；
- **「合并」= 把审过的副本内容采纳为产物**（不是 git merge）；
- ★ **同一内容 sha256 必须在「派审 / 审核 / 批准」三处一致**，任一不等报
  `BLOCKED_CONTENT_MISMATCH`，**不合并**。

## 三、卡片规格（每张卡的必含字段）

```yaml
---
id: W2-C6                    # 唯一编号
mode: 实施                   # 实施 / 验证 / 文档
wave: 2                      # 波次
depends: [W2-C3]             # 依赖卡
task_branch: 无              # 本项目恒为「无」
review_level: R3             # R0–R3
定档理由: |                  # ★ 必写：命中哪条触发条件 + 门禁强度事实
  ...
来源: <审核报告章节 / 契约条 / Owner 裁决>
base:                        # ★ 逐文件内容基线
  - path: 02-backend-node\src_restored\schedules\collect-confirm-task.js
    sha256: 5930df72...
    bytes: 6124
    eol: LF
allowed_paths: [...]         # 可写范围（白名单）
forbidden_paths: [...]       # 禁写范围（黑名单，含理由）
verify: [...]                # ★ 机械可判定的命令
packages: {}
---
```

### ★ 四条硬性要求

1. **`定档理由` 不写 = 未定档。** 必须写明「命中哪条触发条件」+「门禁强度事实」。
2. **`base` 必须逐文件记 `sha256 + bytes + eol` 三元组。**
   ★ 现有教训：卡片曾把 `eol: LF` 写给实际全 CRLF 的 `qianke.sql`
   ⇒ 若按卡行事，执行者会把 548 行全改成 LF，**diff 膨胀 + 触发脱敏连锁差异**。
3. **`forbidden_paths` 必须写理由**，而不只是列路径。理由让后续卡能判断"能否松动"。
4. **单一写者原则**：跨卡共享的文件，必须**显式指定唯一写者**；
   其他卡把它列入 `forbidden_paths`（只读）。

### 规模预算

单卡 **≤ 35k 字节** 且 **≤ 400 可执行行**。

## 四、档位（R0–R3）与触发条件

| 档 | 触发 | 审核配置 |
|---|---|---|
| **R0** | 无代码改动、纯文档，且 verify 可机械判定 | **不派**独立审核 |
| **R1** | 规格已写死在卡里、判断空间小 | 派 **1 名**（可在波次末批量 3–5 张） |
| **R2** | 命中「高风险路径」；或门禁属弱断言 | 派 **2 名**（**必须异质**） |
| **R3** | 命中「真高危路径」；或「该类别历史出过 P0」；或产出**判据本身** | 2 名 + **1 名专项**（安全/权限），**或按停靠点交 Owner** |

### 定档的最高原则

> **门禁越弱，审核越深。**

★ 本项目**多数 verify 属「仅构建 / 仅规范检查」，没有行为断言**
⇒ **这些卡必须升档，不得因为"门禁绿了"而降档。**

### 高风险路径（**路径级，人工维护，不得按关键词自动分类**）

**真高危 → 命中即 R3**：

```

01-backend-go/api/v1/app/collect_release.go       占位释放
01-backend-go/middleware/service_token.go         服务间鉴权
02-backend-node/src_restored/core/collect/*       链上归集执行体
02-backend-node/src_restored/core/collect-bridge.js  L2→L4 桥
02-backend-node/ecosystem.config.cjs              实例数（影响并发归集）
```

**高风险 → 至少 R2**：

```

07-db/schema/qianke.sql + 07-db/migration/**    迁移
05-ios/coruna/payloads/manifest.json            载荷清单

```

**判据级 → 命中即 R3**（产出或修改判据本身）：

```

```

### 审核者配置：为什么必须「异质双层」

检出率经验值：**1 人 ≈ 60% → 2 人 ≈ 75% → 3 人 ≈ 82%**（第 3 人起递减）
⇒ **每卡最多 2 名审核者**。

**必须双层异质**：
- **信息层**（看到什么）
- **能力层**（用什么方法）：
  - **A 路 = 静态抽取**（适合资金口径、契约一致性、清单核对）
  - **B 路 = 运行时实测**（适合并发、锁、端到端）

★ **每路必须在 Verdict 里单独回答「我这一路为什么可能漏」。**
★ 两路都写不出差异 ⇒ **视为同质双审，按 R1 记账**，不当作 R2。
★ **不得共享同一份副本**（本项目的 3.8 GB `node_modules` 与 Go 模块缓存，一次污染会同时污染两路）。

## 五、调度的固定动作（每张卡 12 步）

| 步 | 动作 | 本项目适配 |
|---|---|---|
| 1 | **基线检查** | 确认在 `E:\USDT项目`、无未授权改动。**无 git ⇒ 无"当前分支"可查**，改为核对卡片 `base` 的 sha256 与现树逐文件相符 |
| 2 | **【定档】** | 按 §四给 R0–R3，**写下理由**。定不出 → 按更高一档 |
| 3 | **取内容基线快照** | 逐文件 `sha256 + bytes + eol` 写入卡片 `base`（**不建分支/工作树**） |
| 4 | **`task_branch` 写「无」** | — |
| 5 | **派执行者** | 卡片全文 + **副本路径**。★ **一卡一份仓外副本**（须含 `node_modules` / 运行产物）；★ **必须显式声明副本从哪来**（源路径 + 取副本时刻 + 关键产物 sha256） |
| 6 | **【复核】自己重跑该卡 verify** | 取**自己会话里的真实退出码**，与执行者自报**逐位比对**。不一致 → 未通过，退回。★ **取退出码不接管道** |
| 7 | **提交** | **无 git ⇒ 提交动作改为「确认副本内容 sha256 + 写入台账」** |
| 8 | **派审核** | R0 不派；R1 派 1；R2 派 2（**当场派，互不可见**）；R3 加专项或交 Owner |
| 9 | **处置 Finding** | **P0/P1 → 停下升级 Owner，不自动修订**；P2 → 退回重跑第 6/7 步；P3 → 登记不阻断；两轮未解 → 逐条裁决记理由；**双审分歧不取并集不取交集，由调度裁决留痕** |
| 10 | **内容 sha256 一致核对** | 三处（派审/审核/批准）必须一致，否则 `BLOCKED_CONTENT_MISMATCH`，不合并。**审核后内容变化必须重审** |
| 11 | **合并** | 无 git ⇒ **"合并" = 把审过的副本内容采纳为产物**；冲突 → 中止进 BLOCKED，**不手工硬解** |
| 12 | **台账 + 清理** | 追加一行（档位与理由 / 副本来源 / 三处 sha256 / verify 证据 / Finding 与分歧处置摘要）；★ 写完看台账余量，低于阈值就拆 |

## 六、并行规则（这是本项目并行的判据，不是组织架构）

### 五条契约线

**调度只有 1 个。** 分的不是"调度"，而是 ①卡的**分组标签** ②审核者的**视野分工**。

| 线 | 内容 | 契约源 |
|---|---|---|
| **A 资金与记账** | `01-backend-go` 归集分账 / 结算 | `bill` 分账口径 + **chain 词表** |
| **B 归集执行与互斥** | `02-backend-node/src_restored/core/collect*` | `/app/collect-*` 三端点 |
| **C 载荷分发与 entries** | `02/templates` + `05-ios/coruna`(**只读**) | `entries` **15 项** + `moduleBelongsToChain` |
| **D 前端** | `03-web-admin` / `04-landing` | ⚠️ **两条独立契约**：管理台→Go:8888；落地页→Node:3000 |
| **E 脱敏与门禁** | `build_unified.ps1` + `_fix_work\verify_*` | 脱敏模式集 |

### ★ 并行四条件（四条件全中方可并行）

1. **文件级不相交**
2. **依赖图无传递可达**
3. **无串行边**
4. **不共用同一契约源**

⇒ **同一条线的两张卡默认不并行**（条件 ④）。

### 并行度

```
并行度 = min(合格卡数, 调度当轮能审完的卡数, 5)
```

### ★ 超出机械判据的工程判断（本轮新增）

机械四条件**不足以**覆盖语义耦合。**本轮实例**：

> `F1-C4`（改 `WORKERS` 默认值）与 `I1-C2`（在 `app.js` 新增受 `instanceId` 控制的写入点）
> **文件不相交、依赖无传递可达** ⇒ 形式满足四条件。
> 但二者**语义耦合**（都在决定"多实例下谁干什么"）。
> ⇒ **建议串行**，避免"在错的并发前提下新增写入点"。

**规则化表述**：四条件通过后，调度**仍须自问**——
「这两张卡是否在**同一个运行时语义**上做假设？」
若是 ⇒ 串行，并**在台账写明理由**（不能只写"四条件通过"）。

## 十、台账（Ledger）规范

**记录什么**：记录「**树上真有什么**」，不记录「会话里说过什么」。

**行格式**：

```
## <编号> · <波次/阶段> · <卡号或动作> [R档]
- 档位理由：命中哪条触发条件 + 门禁强度事实
- 副本来源：源路径 + 取副本时刻 + 关键产物 sha256
- 三处内容 sha256：派审 / 审核 / 批准（未派审填「—」）
- verify 证据：命令 | 真实退出码 | 输出尾部（★ 取码不接管道）
- Finding 与分歧：P0–P3 摘要 + 处置；双审分歧的逐条裁决
- 规模：实测字节 / 可执行行（写明单位）
- 余量：本行后剩余（< 5,000 字符则拆件）
```

★ **台账不得写凭据明文、只写值名**
（否则台账自身成为泄漏点，与「定义检测模式的文档在产物内」同类自指 —— P-4）。
★ 台账目录为**新增** ⇒ `_manifest.sha256` 须随之过账，按既有规则在**全部卡完成后单独重算**。
