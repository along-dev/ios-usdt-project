### F-09（P1 · 阻断 · **运行器缺陷**）`_pid_alive` 在中文 Windows **恒返回 True** ⇒ 锁**永不自愈**
FILE: `iso_run.py:226-229`（`_pid_alive`）· `:232-245`（`acquire_lock`，**本 delta 新增**）
BEHAVIOR: 现状 = `_pid_alive` 只判 `tasklist` 的 **stdout 非空**；而中文 Windows 下 `tasklist` 查"无匹配"时**会把提示行打到 stdout** ⇒ **恒 True**。期望 = 对不存在的 PID 返回 **False**。
**最小复现（我实跑）**：
```
tasklist /FI "PID eq 999999" /FO CSV /NH
  → 信息: 没有运行的任务匹配指定标准。      ← 打到 stdout（非空！）
_pid_alive 会返回 = True   <-- 期望 False
```
**现场确证**：锁内持 PID **9448**，而该 PID **不存在**，`iso_run` 仍报
`RuntimeError: ★ 拒绝并发：已有 iso_run 在跑（PID 9448）` ⇒ **"持有者已死即接管"（`:239` 的承诺）失效**。
⇒ **后果链**：一旦异常退出（如被 `head` 截断、或 Ctrl-C）⇒ 锁**永久卡死** ⇒ **唯一恢复手段是手删锁文件** ⇒ **而手删又打开了并发窗口**（见 F-10）。
REMEDIATION: 锁内除 PID 外记**进程创建时间**（或随机 token）并同时校验；或改用 **OS 级文件锁**（`msvcrt.locking` / 独占打开句柄）—— 不用 PID 探测。
ACCEPTANCE: 持锁进程被杀后，下一次 `iso_run` **自动接管**（不报错、不需手删）；两个 `iso_run` 并发时**第二个必被拒**。
GATE_IMPACT: **阻断**（该入口是本卡指定的唯一运行方式）

### F-10（P2 · 阻断 · 与 F-09 连体）**并发 `iso_run` 会互相破坏库结构** ⇒ `ISO_RUN` 不可作稳定闸
EVIDENCE（本次 C 轮）：失败项含
`Error 1146: Table 'qk_e2e_test.bill' doesn't exist` —— 这是**另一方正在跑 schema 克隆（`DROP TABLE`+`CREATE TABLE LIKE`）**的瞬间被撞上；同轮另有大量 `WinError 10061 连接被拒`。
**并且我实测**：轮 C 期间 另有 **PID 2240 的 `iso_run` 持锁在跑**（`Get-CimInstance` 命中其命令行）；我**未动它**（可能是别的会话的）。
⇒ 因 F-09 使"手删锁"成为**唯一**恢复手段，**手删即放行并发** ⇒ 两个 `iso_run` 同灌 `qk_e2e_test` ⇒ **`bill` 表被 DROP 的窗口 + 服务重连 ⇒ 假红**。其 `acquire_lock` 注释自述的假红形态（"`code=7` 却 `bill=3`"）与此同源。
REMEDIATION: 修 F-09（锁能自愈）＋ **把 schema 克隆改成不 DROP 的形态**（或加"运行中"哨兵使并发的第二个在**克隆前**就退出）。
