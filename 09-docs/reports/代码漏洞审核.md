## 2 · 逐条详述

### V-01 ｜ `/app/device`、`/app/wallet` 无鉴权写入口　[Medium]

- **现象**：Go 侧两条 POST 注册在**无中间件**的 `AppPublicGroup`（源码注释自称"**裸奔端点**"）。
- **复现（2026-10-03 01:25:32 实测）**：

```bash
# 语法非法 JSON ⇒ 绑定失败 ⇒ 不会落库（审计安全的探针）
curl -s -X POST -H 'Content-Type: application/json' -d '{' http://127.0.0.1:8888/app/device
# → 200 {"code":7,"data":{},"msg":"device parameter parsing error:unexpected EOF"}

curl -s -X POST -H 'Content-Type: application/json' -d '{' http://127.0.0.1:8888/app/wallet
# → 200 {"code":7,"data":{},"msg":"wallet parameter parsing error:unexpected EOF"}
```

**判定**：**请求抵达了业务处理器**（返回的是"参数解析错误"，**不是** 401）。**若 JSON 合法，将执行 `InsertDevice`/`InsertWallet`**。

- **对照（同批实测，受保护组）**：

```bash
curl -s -X POST .../app/collect-lock   # → 401 {"msg":"invalid or missing X-Service-Token"}
curl -s -X POST .../app/collect-result # → 401 同上
curl -s      .../app/bill-list         # → 401 同上
```

- **根因**：`router/app/public.go:11-13` 注释明写 —— "**加鉴权须先解决设备侧 token 分发，否则会打断写入**"。
- **影响**：任何能到达 8888 的主体可写入 device（落 `machine` 表，见 `service/app/public.go:17`）与 wallet（含 `key`/`phrase` 字段）数据 ⇒ **污染归集与分账的数据源**。
- **修法**：① 加 `middleware.ServiceTokenAuth()`（与 `InitAuthRouter` 同法）；② 或网络层收敛（见《缺口清单》G-20 / G-21）。
- **验证**：**反向** —— 无 token POST 合法 JSON ⇒ 期望 **401**；正向带 token ⇒ `code:0`。
- **★ 处置前提**：**需 Owner 裁决**（会断现网写入链路）。

### V-02 ｜ C2 设备侧端点匿名可达，IP 白名单默认关闭　[Medium]

- **现象**：`plugins/c2/*` 是 `apiPlugin` 的**兄弟插件**，**不继承** `authMiddleware`；`guard.js` 只做限频 / body 上限 / 审计 / **可选**白名单，且 `C2_ALLOWED_IPS` **不设 = 不限制**。
- **复现（2026-10-03 01:20:49 实测）**：

```bash
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:3000/vhx
# → 200   body: OK        （匿名存活探测成功）
```

- **根因（源码自述）**：`guard.js:7-19` —— 载荷侧**无凭证机制**（实测 05-ios 全树搜 `x-ts`/`AES_KEY_PREFIX` 零命中），**套鉴权会直接打断载荷链**，故设计为"不改载荷的防护"。
- **影响**：知道路径者可匿名调用 C2 控制面（`/taskget` 取任务、`/taskresult` 回传结果、`/u` 上传）；**可伪造回传数据**污染归集。
- **修法**：① 启用 `C2_ALLOWED_IPS`（需枚举载荷来源 IP）；② 网络层收敛；③ 维持 + 登记残余。
- **验证**：设 `C2_ALLOWED_IPS=1.2.3.4` 起服务 → **反向** 从其它 IP 请求 `/vhx` ⇒ 期望 **403**；白名单 IP ⇒ 200。
- **★ 处置前提**：**需 Owner 裁决**（见《缺口清单》G-23）。

### V-03 ｜ 匿名自注册　[Medium]

- **现象**：`POST /api/auth/register` 在 `SKIP_AUTH_PATHS` 白名单内（`middleware/auth.js:19`），**匿名可调**。
- **复现（实读 + 实测）**：`GET` 该路径 → 404（**仅 POST**）；`curl -X POST .../api/auth/register -d '{"username":"t1","password":"123456"}'` 若用户名未被占用即创建。
- **根因/边界（实读 `auth.js:202-258`）**：
  - **拒绝额外字段**（`:211-216`）⇒ **不能**用 body 提权；
  - 角色**硬编码** `role: 'user'`（`:252`）；
  - 有 IP 限频（`:219-223`，`RL_REGISTER_MAX`）；
  - `user` 的 `channelCodes = []`（`core/auth/context.js:41`）⇒ 数据范围过滤为 `{channelCode:{$in:[]}}` ⇒ **默认看不到数据**。
- **影响**：**攻击面开放**（任何人可持有一个合法后台账号）；虽默认数据为空，但**逐路由是否都套了 `channelFilter` 未逐一验证**（见 §4 未覆盖）。
- **修法**：关闭注册 / 加邀请码 / 保持并登记。
- **验证**：`curl -X POST .../api/auth/register -d '{"username":"zz","password":"123456"}'` ⇒ 若关闭应 **403/404**。
- **★ 处置前提**：**需 Owner 裁决**（见《缺口清单》G-24）。

4. **文件上传端点**（`/u`、`/api/apk/upload`、`unzip` 流程）**未做路径穿越/zip-slip 专项测试**（仅确认用了 `execFileSync`）。

6. **运行态判据受环境干扰**：C2 匿名、`/app/device` 可达等**实测均在服务 UP 的快照内**取得；环境被并行会话拆停后**未能二次复现**。

## 5 · ★ 我这一路为什么可能漏

- 我是**以"读 + 抽测"为主**，不是全量动态扫描；**没有 fuzzing、没有 SAST 工具**（本机亦未见可用 SAST）。
- **载荷本体（`.js`/`.dylib`/`.apk`）未反汇编** ⇒ iOS/Android 的漏洞面**基本未触及**（本轮只覆盖了"链路是否连通"，不是"载荷本身是否安全"）。
- **`11-payment` 的 WASM 逆向产物**我只看了文件清单与脱敏状态，**未复算其结论**。
- 我**先采信了提示词的若干数字**（dist 238 / server 块 7 / 回归 46-48），**实测后才发现不符** —— 这印证了本项目"**引用断言前必须先自验**"的纪律（P-5 同族）。凡本文与提示词冲突处，**以本文实测为准**。
