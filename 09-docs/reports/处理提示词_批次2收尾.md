### ★ 任务 2：`verify_t22_bill_endpoint.py` 收尾

#### 2.1 现状（**主审实读源码**）


**★ 主审已用 DB 直查确认**：`qk_e2e.bill = 43 行` ⇒ **数据真实增长，脚本期望过时**。

#### 2.2 ★★ 根因已由主审定位并复现（**直接照做**）

**根因**：`:100` 调 mysql **没有加 `--skip-ssl`** ⇒ **TLS 握手中断**；
而 `:107` 用 `except Exception: pass` **静默吞掉**异常 ⇒ 返回 `None`
⇒ 回落到 `:256` 的静态 `EXPECTED_BILL_TOTAL = 33` ⇒ **V4 判 FAIL**。

**主审复现（决定性）**：
```
不带 --skip-ssl（= t22 的调用方式）：
  ERROR 2026 (HY000): TLS/SSL error: no credentials. Error 0x8009030E(SEC_E_NO_CREDENTIALS)
  EXIT=1                                    ← ★ 失败，且被 except 静默吞掉

带 --skip-ssl：
  43
  EXIT=0                                    ← ★ 正确值
```

**⇒ 修法（最小改动）**：
1. ★ 在 `:100` 的命令行**加 `--skip-ssl`**
2. ★★ **删除 `:107` 的 `except Exception: pass`** —— **静默吞异常是本缺陷的放大器**
   （应改为：**拿不到 DB 值 ⇒ SKIP，而不是 fallback 到旧静态值判 PASS**）
3. 把 `EXPECTED_BILL_TOTAL` 降级为**纯注释/兜底**，**主路径走 DB 动态值**

★ **这是一条普适教训**：**"静默兜底 + 静态期望"= 假红/假绿的双重来源**。

#### 2.3 你要做的（补充确认）

- 改后**确认 `db_total` 真的取到了值**（打印 "DB 实查 = 43" 一类证据）
- ★★ **若 DB 不可达 ⇒ 必须 SKIP**，**不得 fallback 到 33 判 PASS**（**P-13**）

#### 2.4 判据
