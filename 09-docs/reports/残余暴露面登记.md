## R-01 · `wallet_id` 只传 device_id 时的半参数放行

**来源**：D0-C4 的 B 路审核（运行时）疑点 ① + 调度实测复核

### 事实

D0-C4 给 `ResolveWalletId` 的 `walletId > 0` 分支加了**交叉一致性校验**，
但**校验有前提**：

```go
if walletId > 0 {
    if deviceId != "" && address != "" {     // ← ★ 仅当【两者均非空】才校验
        // 交叉校验 ...
    }
    return walletId, nil                     // ← 缺省时直接放行
}
```

### 复现（实测）

```
GET /app/wallet-status?wallet_id=1&chain=tron&device_id=dev-e2e-001
  (不传 address)
=> code=0 ok            ← 校验被整体跳过
```

### 影响

持**共享服务 token**（`X-Service-Token`）者，**仅凭 `device_id`** 即可
查询**任意 `wallet_id`** 的状态（`progress` / `region`）。

★ 更关键的是：该 token 也用于 `/app/collect-lock` / `/app/collect-result`，
⇒ 理论上可对任意 wallet 发起 lock / release / result。

### 为何**不修**（有意保留）

1. **`wallet_status.go:38` 的注释明确要求**「`wallet_id` 与 `device_id+chain+address` **二选一**」
   ⇒ 若无条件要求三者齐全，**会破坏既有调用**（gasleak / sweeper 侧不持有 wallet id）；
2. **D0-C4 的卡内明列为硬要求**（防改过头）；
3. 真正做到"归属校验"需要 **DTO 增加调用方身份字段** ⇒ **触契约 C-2**（停靠点）。

### 缓解（已存在）

| 缓解 | 事实 |
|---|---|
| **fail-closed 鉴权** | `ServiceTokenAuth` **未配置即拒绝**；无 token / 错 token 实测 **HTTP 401**（B 路补例 A/B 实证） |
| **token 持有面窄** | 该 token 仅 gasleak 服务持有 ⇒ **利用门槛 = 先取得服务间密钥** |
| **已阻断主要越权形态** | **同时传全三者**时，交叉校验生效（R2/R6/F 三例均被拒） |

### 登记人判定

**严重度：P1（残余，非新缺陷）**

★ **建议后续**：
- 若要彻底闭合 ⇒ **立卡改契约 C-2**（给 DTO 加调用方身份）—— **属停靠点，须 Owner 裁决**；
- 若接受现状 ⇒ **本条目即为永久留痕**，后续审核不得据其重复开卡（除非 Owner 改变口径）。

## R-03 · coruna 偏移表覆盖上界之外的设备行为

**来源**：D0-C5 的缺陷本体 + `platform_module.js` 实测

### 事实

`platform_module.js` 的偏移表**最高项为 170300**（iOS 17.3）。
⇒ 运行 **iOS >17.3** 的 coruna 载荷设备，**会套用 17.0 的偏移配置**。

### 为何**不修**

**V0 裁决 D-3** 明裁：「**不改偏移表**，但必须加显式告警」。
⇒ D0-C5 **已按此完成**（加了告警，未改偏移表）。

### 登记人判定

**严重度：P2（已裁决保留的技术债）**

★ **残留风险**：iOS 17.4–18.3 的设备理论上**可能执行失败**（偏移不匹配）。
★ **缓解**：D0-C5 的告警使该情形**可观测**（不再是静默失效）。
★ **彻底解决**需真机实测（**D-4 未授权**）或扩展偏移表（**D-3 明裁不做**）。

## R-04 · 客户 settlement 无归属过滤（D0-C3 停靠点）

**来源**：补审报告 P1-4 + 调度实测

### 事实

`collect_result.go:330-355` 的 `customSettlementId/Addr` 与 `scan.go:80-82`：

```go
Model(app.Custom{}).
    Where("settlement.chain LIKE ?", "%"+chain+"%").      // ← 仅链过滤
    Joins("left join settlement on settlement.user_id = custom.user_id").
    Limit(1)                                              // ← 无 ORDER BY，取任意行
```

**对照**：同文件 `scan.go:70` 的**代理侧**有 `machine.id=?` 约束 ⇒ **不对称**。

### 为何**未修**（停靠点）

**`custom` 表结构实测为 `id / user_id / usdt_num`** ⇒
**无 `machine_id`、无 `agent_id`** ⇒ **schema 层面无法从 machine 推出"其客户"**。

⇒ **这不是纯技术缺陷，而是数据模型缺字段 + 业务语义未定义**。

### 登记人判定

**严重度：P1（未修，待业务裁决）**

★ **危害**：多客户库中，**客户分成可能落到与该钱包无关的客户**。
★ **缓解**：当前若为**单客户运行**（如 e2e 库仅 1 个 custom），危害不显现。
★ **须 Owner 裁决**：定义"一个 machine 对应哪个 custom"，或明确接受该残余。
