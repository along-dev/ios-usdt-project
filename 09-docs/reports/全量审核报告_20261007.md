## 三、⚠️ 回归集从 95.8% 跌到 67.3%（**本轮最重要的发现**）

**实测（`run_regression_v2.py`）**：
```
PASS 33 / FAIL 16 / TIMEOUT 0 / KNOWN-GAP 1  (共 50)
通过率 33/49 = 67.3%
跑后六端口全 UP ✅（护栏仍生效）
```

**16 个 FAIL 我逐类定性（见下），结论：不是同一根因，分三类**：

### 3.1 类 A：fail-closed 守卫生效（**不是缺陷，是 AD-02 修复落地**）

3 个资金判据现在**拒绝裸跑**：
```
verify_f1c8_amount_guard.py   →  AssertionError: ⛔ 拒绝裸跑：只允许隔离库 qk_e2e_test（须经 iso_run.py 注入）
verify_f1c9_toaddress_guard.py → 同上
verify_money_path.py           → 同上
```

★ **这是 AD-02（危险默认值）被修好的表现** —— 判据现在**默认 fail-closed**，
不再裸连业务库。**代价是**：裸跑回归集时这 3 个判据"红"。
⇒ **正确，但回归集口径须改**：要么设为 `set YES`，要么把这些判据**从"裸跑主集"移到"须注隔离库"集**。

### 3.2 类 B：环境差异（**非代码缺陷，但掩盖了真实测试**）

`verify_f1c11_cache_key.py` 的 5 个 FAIL：判据用 `Host: 127.0.0.1` 打 `/details/show.html`，
而渠道白名单里**没有 `127.0.0.1`** ⇒ 全返回 `{"unsupported":true,"reason":"no_channel_for_host"}`。

★ **核实（实读 `config-builder.js:14-16`）**：
```js
if (!channel) { return { unsupported: true, reason: 'no_channel_for_host' }; }
```
⇒ **payload 路由的 fail-closed 在正确工作**（未知 Host 不产出载荷 —— **这本身是安全行为**）。

★ **但判据因此无法测到"缓存串味"** —— 它的 C1/C2/C4 全部因"拿不到 channel"而失效。
⇒ **判据与环境脱节**：需要给判据一个**真实 channel 的 Host**（或其测试期实现的 channel 注入路径）。
