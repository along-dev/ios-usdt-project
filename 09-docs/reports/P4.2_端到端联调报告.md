## 三、★ 联调发现的两个真 bug

### Bug 5（我的设计缺陷）：唯一索引与多行分账根本冲突

| 项 | 内容 |
|---|---|
| 现象 | 首次回传即 `Error 1062: Duplicate entry '0xE2E_TEST_001' for key 'uk_transfer_hash'`，bill 表 **0 行** |
| 根因 | 我设计的 `UNIQUE KEY (transfer_hash)` 是**全列唯一**，<br>但分账需为**同一笔交易写 3 行**（role 1/2/3）→ 第 2 行必然冲突 → 事务整体回滚 |
| 独立复现 | 直接插 3 行同一 tx_hash，**仅第 1 行成功**（见 `e2e_prove_unique_conflict.py`） |
| 修复 | 唯一键改为**复合键 `uk_txhash_role (transfer_hash, role)`**<br>—— 保证"同一交易的同一角色只有一行"，同时允许分账多行共存 |
| 验证 | 修复后 3 行全部入库，幂等仍生效 |

**这是只有端到端联调才能发现的缺陷**：静态检查、单表迁移、甚至"幂等复跑"都通过，
但**真实调用一次就暴露**。

### Bug 6（既有代码缺陷，非我引入）：`custom` 表无 `ratio` 列

| 项 | 内容 |
|---|---|
| 现象 | `ERROR 1054 (42S22): Unknown column 'custom.ratio' in 'SELECT'` |
| 位置 | `blockchain/scan.go` 的 `Sk()`：<br>`Select("settlement.id, settlement.address, custom.ratio, custom.user_id")` |
| 实测 | `custom` 表实际只有 **`id` / `user_id` / `usdt_num`**；<br>`Ratio` 只存在于 `agent` 表 |
| 影响 | `Sk()` 的**客户分成查询必然失败** → `customAmount` 计算不出来 |
| 我的实现 | **未重复该错误**：客户分成按残差计算（`1 - techFee - agentRatio`），与 `Sk()` 下游公式一致 |
| 处置 | 记为 **N-11**，未修改既有代码（超出 §4.2 范围） |

## 四、另发现的安全问题（N-12）

**`/app/*` 端点全部未鉴权。**

```
未带任何 token：
  GET  /app/wallet-status?wallet_id=1  → HTTP 200 {"progress":0,...}
  POST /app/collect-result             → HTTP 200 {"msg":"txHash is required"}
  POST /app/device（既有端点）          → HTTP 200 {"msg":"record not found"}
```

`initialize/router.go` 实测：

```go
AppPublicGroup := Router.Group("")        // ← 没有 .Use(middleware.AppJWTAuth())
appPublicRouter.InitPublicRouter(AppPublicGroup)
```

`middleware/app_jwt.go` 的 `AppJWTAuth()` **存在但从未被挂载**。

- **性质**：**既有缺陷**（`/app/device`、`/app/wallet` 本来就不鉴权），我的新端点继承了同样行为
- **§3.2 方案里写的"鉴权：AppJWTAuth"与实际不符**
- **风险**：任何人可查询钱包收割状态、伪造归集结果写入 bill（**污染分账数据**）
- **处置**：记为 **N-12**，**未擅自修改**（涉及全局鉴权策略，需你决策）

## 七、新增发现

### N-11 `Sk()` 查询不存在的 `custom.ratio` 列

见上文 Bug 6。建议单独排期修复：`Sk()` 的客户分成应改为残差法，
与 `collect-result` 的实现保持一致。

### N-12 `/app/*` 端点未挂 `AppJWTAuth`（安全）

见上文第四节。**建议优先处理**：归集回传端点可被任意调用并写入分账数据。

### N-13 `apply_patches.py` 非幂等

在**已打过补丁**的工作区重复执行会导致重复插入（`ReqCollectResult redeclared`、
`BtcAddress redeclared`）。
→ 修法：每次从干净副本重建，或给脚本加锚点检测（已有 `old not in s` 判断，
但新增文件的 `add_file` 无守卫）。
