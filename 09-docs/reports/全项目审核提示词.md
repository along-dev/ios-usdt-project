## 五、★★ 审核方法（**必须遵守，这是前几轮的教训**）

### 5.1 三态判定（**每个结论必须落三态之一**）

| 态 | 含义 |
|---|---|
| **已验证为真** | 有可复现的证据（命令 + 输出） |
| **已验证为假** | 同上 |
| **未验证** | ★ **如实标注**，**不得写成"应该是"** |

★ **"通过"不等于"正确"** —— 静态判据全绿也可能功能没做。

### 5.2 每条结论必须锚定

- **`file:line`** 或 **可复现命令**
- **运行态数字必须带时点**（服务会被杀，端口状态不是持久事实）
- ★ **引用断言前先贴 import 的绝对路径**（**P-1**：别把"源目录"的成绩记成"产物的"）

### 5.3 ★★ 必须做"反向断言"

**只测"应当通过"不够**，**必须测"应当失败"**：
- 测鉴权 ⇒ **证明无 token 被拒**
- 测防护 ⇒ **证明攻击被挡**
- 测绑定 ⇒ **证明该连不上的连不上**

### 5.4 ★★ 主审本轮踩过的坑（**你别再踩**）

| 坑 | 说明 |
|---|---|
| **P-5 量尺错误** | ★ 主审两次因"量尺/前提错"得出**反向结论**：① 用不带 `-Recurse` 数文件得 0，误判"目录为空"；② **用猜的路径探路由得 404，误判"seed 与路由不一致"**（真实路径取自 `sys_apis` 表后全部正常） |
| **看错文件** | ★ `init/index.vue` vs `home/index.vue` → **文件名相似 ≠ 同一文件**，按名定位须**同时核对路径与 mtime** |
| **契约误读** | ★ **Go 侧业务失败也返回 HTTP 200**（`code` 在 body）；**Node 侧**才用真实状态码 ⇒ 主审一度误判"鉴权失效" |
| **静默兜底** | ★ "`except: pass` + 静态期望" = **假红/假绿的双重来源**（t22 就是实例） |
