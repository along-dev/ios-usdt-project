### F-T60-B1 — **`acquire_lock()` 在争抢下漏出 `PermissionError`**（★ 我用轨迹证到行号；不破互斥、但契约不全）

- **SEVERITY**：**P3**（★ 不阻断）
- **FILE**：`E:\ios漏洞\_integration\_fix_work\iso_run.py:322`（`_acquire_take_token` 内的 `os.open(TAKE_TOKEN, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o644)`）· 调用链 `acquire_lock:410 → _try_takeover_and_create:350 → :322`
- **BEHAVIOR**：★ `_acquire_take_token` **只捕 `FileExistsError`**；★ 而 Windows 上令牌文件**正被并发清掉／占着**时，`os.open(..., O_EXCL)` 抛的是 **`PermissionError`（Errno 13）** ⇒ ★ **逃出 `acquire_lock`**；★ 而 `main()` 的 `try` **只有 `finally`、没有 `except`**（`:450` 起）⇒ ★ **异常穿透 ⇒ 抛栈**（★ 设计好的「★ 拒绝并发：已有 iso_run 在跑…」那句提示**被包进 traceback**）。
- **EVIDENCE**（★ 轨迹，⛔ 非推断）：
  ```
  Traceback (most recent call last):
    ... m.acquire_lock()
    File ".../iso_run.py", line 410, in acquire_lock        r = _try_takeover_and_create()
    File ".../iso_run.py", line 350, in _try_takeover_and_create   if not _acquire_take_token():
    File ".../iso_run.py", line 322, in _acquire_take_token
  ```

  ★ **发生率（我实测）**：N=16 单轮 `{LockContention:10, got:1, LockBusy:2, PermissionError:3}`；★ 批跑汇总 **现版 N=16×8 共 41 个**、**N=32×8 共 37 个** ⇒ ★ 约占**争抢者的 1/3**。
  ★ **对照**：★ 把令牌的 `O_EXCL` 拿掉后该类异常几乎消失（N=16×8 共 0 个、N=32×8 共 10 个）⇒ ★ **确系令牌的 `O_EXCL` 创建路径所致** ✓
