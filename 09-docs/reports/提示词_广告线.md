## 三、任务

### W-AD-01（R2）· **渠道 → 包 → 落地页 的绑定**（★ 先做，后面都依赖它）

| 步 | 做什么 |
|---|---|
| 1.1 | 在 Node `channels` 模型补 `packetId`（对齐 Go `packet.group_id` 或 `packet.id`）与 `agentId` |
| 1.2 | `/api/channels` 的 CRUD 支持这两个字段（**扩展现有端点，勿新建平行路由**） |
| 1.3 | 提供反查：`GET /api/channels/:code` 返回所属 `packet` 与 `agent` |

**判据**：建一个渠道 ⇒ 能反查到所属包与代理商；**反向**：代理商 A 查不到代理商 B 的渠道。

### W-AD-02（R1）· 渠道 / 来源域名 管理页

**复用**：`03-web-admin` 现有布局与 `src/api` 封装模式（参照 `src/api/index.js`）。
**新建**：你自己的子目录（如 `src/view/channel/**`），**并在 `sys_base_menus` 加菜单项**（与后台线协调，勿撞）。
**接**：`/api/channels`、`/api/source-domains`。
**判据**：页面可增删改查；操作后 Mongo `channels` 条数从 **0 → >0**（可观测）。

### W-AD-03（R1）· 渠道统计页

接 `/api/channel-stats`、`/api/channel-stats/:channelCode/domains`。
**判据**：页面数值与 Mongo `channeltotalstats` 一致；**反向**：空渠道显示**空态**而非 0 假数。

### W-AD-04（R2）· **APK 按渠道分发**（★ 与安卓线**同一改动**，见 §五）

现状：`plugins/api/routes/landing.js:181-219` 的 `/api/apk/download` **恒取 `files[0]`**，不区分渠道。
改为：按请求渠道/包选择 APK（数据源用现有 `06-android/apk/japapp/{japapp.apk, child_milkstream.apk}`）。
**判据**：渠道 A 下载得包 A、渠道 B 得包 B（**sha256 不同**）；**反向**：未绑定渠道 ⇒ **诚实 404**（不得回退取第一个）。

### W-AD-05（R1）· 落地页模板 ↔ 项目打通

`04-landing/templates/`（**53 个**）· `packet.landing_page` · `/api/template`（`plugins/android/landing.js` 的 `resolveTemplateName`，白名单 `KNOWN_TEMPLATES`）。
**判据**：改 `packet.landing_page` ⇒ 落地页实际切换；模板名不在白名单 ⇒ **回退默认 `vodex`**（反向）。

### W-AD-06（R2）· 代理商/工作室在广告侧的视图

Node 中间件**已有** `request.channelFilter`（`plugins/api/middleware/auth.js:91`）⇒ 给 `/api/channel-stats` 套上它。
**判据**：代理商只看到自己渠道的统计；**反向**：`user` 角色查询返回**空集**而非全量。
