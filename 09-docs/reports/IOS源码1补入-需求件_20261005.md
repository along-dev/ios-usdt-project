## 四、转换规则（★ 含先例锚，这是本件最可操作的一节）

**先例**：USDT 已从同一基准移植过同族文件 —— `schedules/balance-init.js`（**90 行**）← `schedules/balance-init.ts`（**112 行**）。
**逐行对照得到的既定转换法**：

| 规则 | 证据 |
|---|---|
| **`import type { … }` 整行<ins>删除</ins>**（⛔ 不得转成运行时 import） | `balance-init.ts:2,9` 的两条 `import type` 在 `balance-init.js` 中**消失** |

| 类型标注/接口/`as` 断言删除 | 112 → 90 行 |
| **中文注释、字符串字面量、数值常量、控制流一律保留** | 承 Owner 要求 |
| **`export const x: ScheduleTask = {…}` ⇒ `export const x = {…}`** | 同先例 |

★★ **一个必踩的坑**：USDT 的 `schedules/types.js` 是**空壳**（内容只有 `export {};`）。
若把 `import type { ScheduleTask } from './types.js'` 误转成 `import { ScheduleTask } from './types.js'` ⇒ **运行时 `SyntaxError: does not provide an export named 'ScheduleTask'`**。
⇒ **判据**：转换后必须 `grep -n "^import" <新文件>.js`，**不得出现 `ScheduleTask` / `IDerivedAddress` 等类型名**。

### 裁决项 ①：`auto-collect` 算不算「架构冲突」？（★ 原提示词判为"反例"，我建议**复核该判断**）

**实测证据（`E:\IOS源码1\server\src\core\collect\auto-collect.ts`）**：
- `collectTronUsdt()` → `POST https://tronapi.org/api/v1/tron/transfer`，**body 里带 `privateKey`**
- `collectEth()` → `POST https://tronapi.org/api/v1/eth/transfer`，**同样带 `privateKey`**
- `checkEthGas()` → `GET https://api.etherscan.io/…&apikey=**YourApiKeyToken**`（**硬编码占位 key**）
- 即：**签名由第三方服务代做，私钥经 HTTP 出网**。

**为什么这构成冲突疑点**：USDT **既有**一整套**本地签名**归集体系 —— `core/collect/{eth,tron,btc}-collector.js` ＋ `pool.js` ＋ `executor.js` ＋ `config-resolver.js` ＋ `target-pool.js`，外加 Go 侧 `Sk()` 与 `10-sweeper`。
按 §2.3 自己的冲突定义（「同一能力存在**两套并行、语义重叠**的实现」）——**触发策略**确实不同（阈值 vs 定时），但**归集执行**重叠，且**签名机制根本对立**（第三方代签 vs 本地签名）。

| 选项 | 利 | 弊 |
|---|---|---|
| **A. 仍按"反例"补入** | 原样搬入，改动最小 | 引入**私钥出网**路径 ＋ 两个硬外部依赖（`tronapi.org`、`etherscan.io`）；与「验证上限＝静态＋本地服务」冲突；且**注定无法端到端验证**（无外网凭据） |
| **B. 判为冲突，不补** | 保持单一归集机制 | 少一个「阈值自动归集」能力 |
| **C. 只补 `<ins>判定逻辑</ins>`，不补执行** | 保留 `shouldCollectTron/Eth`（纯函数、无副作用、零外部依赖）＋ `checkTronGas/checkEthGas` 的**结构**，执行侧改走 USDT 既有 collector | **属改写非搬运**，超出本任务「保义转换」的边界，须单独立卡 |

★ **本线建议：C**（判定逻辑有独立价值，执行侧不该有两套）。但**这是 Owner 的取舍**，本线不代裁。
★ 另：Owner 已知**本项目钱包全是测试数据** ⇒ **不按真实事故升级**；但**设计事实**须让 Owner 知道后再定。
