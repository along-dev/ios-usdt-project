## 六、★ 我的一处**误判**（**已自我纠正**）

### 6.1 现象（我最初看到的）

探测 Go 侧受保护端点时，**多数返回 404**：
```
POST /api/getUserList         → 404
GET  /api/user/getUserList    → 404
GET  /api/menu/getMenu        → 404
POST /api/authority/getAuthorityList → 404
```
⇒ 我**一度怀疑**「`sys_apis` 100 条 vs 运行时 404 ⇒ seed 与路由不一致」。

### 6.2 ★ 纠正（**我查了 `sys_apis` 的真实路径，发现是我猜错了路径**）

**从 DB 取出 `sys_apis` 的真实路径**：
```
/device/custom_financial   POST      /api/getApiList            POST
/authority/copyAuthority   POST      /device/rk                 POST
/menu/deleteBaseMenu       POST      /autoCode/getDB            GET
```
★ **真实路径多数【没有 `/api/` 前缀】**（如 `/device/financial`、`/authority/copyAuthority`）——
这是 gin-vue-admin 的**路由组风格**，而我**按直觉猜了带 `/api/` 的名字**。

**用真实路径重测**：
```
POST /api/getApiList              -> 200  {"code":7,...,"msg":"未登录或非法访问"}
POST /authority/copyAuthority     -> 200  {"code":7,...,"msg":"未登录或非法访问"}
POST /device/financial            -> 200  {"code":7,...,"msg":"未登录或非法访问"}
POST /menu/deleteBaseMenu         -> 200  {"code":7,...,"msg":"未登录或非法访问"}
GET  /autoCode/getDB              -> 200  {"code":7,...,"msg":"未登录或非法访问"}
POST /device/rk                   -> 200  {"code":7,...,"msg":"未登录或非法访问"}
```

### 6.3 ★★ 结论

**`sys_apis` 的 100 条路径与运行时路由【完全对应】** ✅
（`code:7 "未登录或非法访问"` = **路由存在 + 鉴权正确拦截**，不是 404）。

**⇒ 我的"seed 与路由不一致"怀疑【不成立】** ——
**根因是我用猜测的路径去探测**（**P-5 的又一实例：量尺错了会得出反向结论**）。

★ **方法论教训**：**探测路由时，路径必须取自权威源（`sys_apis` 表 / `[GIN-debug]` 日志），
不得凭直觉拼**。这与台账 R2-2 的 v3 修正（"正则提取源码 ≠ 运行时注册，权威源是启动日志"）**同一条教训**。

**⇒ §六 由"待查异常"降级为"我的误判，已纠正"；无缺陷。**
