## 二 · `F-T53-A`（P2）怎么修的 —— **两条支路<不对称>是根因**

**根因（读码坐实）**：`USE` 支路是**最小替换保壳**（只换库名 token）；而 DD 支路是

```python
edits.append((pos[0], e, "-- [AD09 已剥] " + " ".join(code.split())))   # ⛔ 替换区间 = [代码起点, 语句尾]
```

—— 对 `/*!50000 DROP DATABASE x */;`：代码起点＝`DROP`、语句尾＝`;` ⇒ **把收尾 `*/` 一并吃掉**，
留下**未闭合**的 `/*!50000` ⇒ **畸形 SQL**（MySQL 里**吞掉其后全文**）。

**修法**：改为与 `USE` 支路**同法的最小替换保壳** —— **只替换「自 DDL 关键字起的那一段<ins>连续代码</ins>」**
（⛔ 不跨越任何 trivia ⇒ 版本注释的 `*/` 与前后注释**逐字节保全**），置为**无害空操作** `DO 0`
（该段末尾若是 `;` 则**保留原分号**）：

```
/*!50000 DROP DATABASE x */;   ⇒   /*!50000 DO 0*/;          ★ 外壳保全，MariaDB 执行 DO 0（无害）
DROP DATABASE x;               ⇒   DO 0;                     ★ 纯形态
SET @x:=1;\n/*!50000 DROP…*/;  ⇒   SET @x:=1;\n/*!50000 DO 0*/;
```

★★ **本件在矩阵上**抓到并修掉了**我自己第一版改法的两处缺陷**（**如实留痕**）：
1. **起点取错**：初版取「**首段连续代码**」的起点，而它可能只是**前导空白/换行**（如 `SET @x:=1;\n/*!…`）
   ⇒ 替换的是空白、**DDL 没被中和**（矩阵 **D5/D6** 当场照出）。⇒ 改为取 **DDL 关键字**的偏移。
2. **多出空语句**：初版在带分号时置 `DO 0;` 而**又保留了原分号** ⇒ 产出 `DO 0;;`（矩阵 **D7/D8** 照出）。
⇒ ★★ **同时暴露了判据太弱**：初版只看「保壳 ＋ 改写」⇒ **D5/D6 会被误判为通过**（它确实"改了"，只是**改在了空白上**）。
⇒ **判据现为三合一**：**保壳（`/*!`/`*/` 计数不减）＋ 改写（≠输入）＋ <ins>DDL 净</ins>（中和后**代码视图**里不再有 DDL）**。
