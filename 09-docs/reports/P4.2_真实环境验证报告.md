### 关键障碍与解决

**① 网络：PowerShell/curl 全部失败**
```
curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS
```
根因是 **Windows schannel 凭证获取失败**，不是网络不通。
→ 改用 **Python（自带 OpenSSL 3.0.16）** 下载，成功：
```
https://goproxy.cn               -> HTTP 200
https://golang.google.cn         -> HTTP 200
```

**② `Start-Process` 报字典冲突**
```
Item has already been added. Key in dictionary: 'NO_PROXY' Key being added: 'no_proxy'
```
→ 先清除大小写重复的代理环境变量；并用**托管后台作业**启动 mysqld（否则进程随 pwsh 调用结束被杀）。

**③ `GOCACHE` 被沙箱拒绝**
```
failed to initialize build cache ... Access is denied
```
→ 把 `GOCACHE`/`GOTMPDIR` 指到工作区内。

**④ MariaDB 客户端同样报 schannel 错误**
→ 加 `--skip-ssl`，连接成功。

## 三、★ 真实验证抓出的 4 个 bug（静态检查全部漏掉）

这 3 类问题**只有真执行才能发现**，正是本次环境补齐的价值。

### Bug 1：`sys_dictionary_details.value` 是数值列，存不了字符串

| 项 | 内容 |
|---|---|
| 现象 | `ERROR 1366 (22007): Incorrect integer value: 'gasleak' for column value` |
| 根因 | 实测列定义 `value bigint(20)`，**非 varchar** |
| 影响 | `collect.mode` 开关写不进去；且**报错了脚本仍 exit=0**（见 Bug 3） |
| 修复 | 改按该表原生设计：**`value` 存数值码 `1/2/3`，`label` 存可读名**；Go 侧 `collectMode()` 映射回字符串 |

### Bug 2：备份表被覆盖，导致回滚失效

| 项 | 内容 |
|---|---|
| 现象 | 执行两次隐藏脚本后，回滚**什么都没恢复**（仍 `15/0`，期望 `4/11`） |
| 根因 | 备份用 `DROP TABLE IF EXISTS ...; CREATE TABLE ... AS SELECT`，<br>**第 2 次执行时把备份覆盖成了"已隐藏"状态** |
| 修复 | 改为 `CREATE TABLE IF NOT EXISTS` + `WHERE NOT EXISTS` 补插，**备份只建一次、永不覆盖** |
| 验证 | 修复后回滚恢复 `4/11`，且 id 1/8/25 原本隐藏项未被误改 |

### Bug 3：迁移脚本报错但 exit=0（静默失败）

| 项 | 内容 |
|---|---|
| 现象 | Bug 1 的 `ERROR 1366` 发生后，`mysql < file` **仍返回 exit 0** |
| 根因 | `PREPARE/EXECUTE/DEALLOCATE` 包裹的语句出错，错误在 server 端打印，<br>但客户端退出码未反映 |
| 影响 | **CI/自动化会误判迁移成功** |
| 处置 | 已在脚本内加**有效性校验查询**（`collect_mode` 应有且仅有 1 条 `status=1`）；<br>另建议部署时以"校验查询结果"而非 exit code 作为判据 |

### Bug 4（自查过程中的方法论错误）：用被改过的库验证"源状态"

| 项 | 内容 |
|---|---|
| 现象 | 我一度得出"脚手架菜单源数据已全部隐藏，脚本冗余"的结论 |
| 根因 | 查询的库**已被我的前一版脚本执行过**，测到的是"改后"状态 |
| 真相 | 改用纯净库复核：**4 hidden / 11 visible** —— 原判断正确，脚本确有必要 |
| 教训 | **验证"源状态"必须用从未被改动过的库** |

### N-10 MariaDB 客户端需 `--skip-ssl`

本机 schannel 无法获取 TLS 凭证（`SEC_E_NO_CREDENTIALS`），
导致 `mariadb.exe` 默认连接失败。
→ 所有脚本加 `--skip-ssl`。这是**本机环境问题**，非产品问题；
但在同类受限环境部署时需注意。
