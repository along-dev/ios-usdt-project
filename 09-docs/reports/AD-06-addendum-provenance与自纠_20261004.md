## 2 · ★ 本线对 T35 复核中 **A-02** 一条的**自纠**（错误入账的落点）

### 2.1 我原来写了什么
在 T35（编号 A）复核的 **A-02** 里，我写了：
> 「全仓 `rg "recover\(\)"` ⇒ **仅 `middleware/error.go:20` 一处**；而 `GinRecovery` 全仓 2 次命中都在同一文件 ⇒ **未被注册**」
并据此在 EVIDENCE 里下了 **「⇒ 本仓实际没有任何 recover 生效」**。

### 2.2 错在哪
**「本仓实际没有任何 recover 生效」这句是错的。** 总调度实测纠正后，**本线自证**：
`01-backend-go/initialize/router.go:37` ＝ **`Router := gin.Default()`**；而 gin 源码（本机 `gin@v1.9.1/gin.go` 实读）：
```go
func Default() *Engine {
	debugPrintWARNINGDefault()
	engine := New()
	engine.Use(Logger(), Recovery())     // ← 自带 gin 内置 Recovery
	return engine
}
```
⇒ **请求链上确有 Gin 内置 `Recovery()` 在生效**。

### 2.3 哪一半仍成立
**「自定义的 `GinRecovery`（`middleware/error.go:17`）定义了却从未被注册」——这一半成立**（全仓 `rg -c "GinRecovery"` ＝ 2 次命中、`middleware/error.go:2` 之外为 0）⇒ **它是个死中间件**。总调度已记下。

### 2.4 ★ 我为什么会写错（根因，与上一轮同族）
我下的是**否定式完整性断言**（"**全仓**没有任何 recover 生效"），但我的检索面**只有本仓源码**，**漏了依赖/框架的【默认行为】这一类出处** —— `gin.Default()` 的语义在 **module cache**（`…/gin-gonic/gin@v1.9.1/gin.go`）里，不在本仓。
⇒ **与我在 `扁平副本取证` 里犯过的两次同族**（只读一处出处就定性）：那两次是**只读了上游链的一步**，这次是**只扫了本仓一层**。**同一种病：把"我检索到的那点"当成"全部"。**

### 2.5 机械落点（供后续同族防犯）
> **凡下"全仓／全局没有 X 生效"这类【否定式完整性断言】⇒ 检索面必须显式包含三处：① 本仓源码 ② **依赖与框架的默认行为**（`module cache` / `vendor`，如 `gin.Default()`＝自带 Logger+Recovery、`gorm.Open` 的默认回调等） ③ **运行期实际装配处**（如 `Router.Use(...)` 链）。
> **给不出这三处的读数，就不许写成"没有"**，只能写成"**我检索到的范围内未见**"并标明检索面。**

### 2.6 影响面（本条错误是否污染了结论）
- **不污染 T35 的 verdict**：A-02 的 SEVERITY 本就是 **P3、非阻断**，verdict 是 **APPROVED（0 阻断）** ⇒ **结论未变**。
- 但它**污染了那条 EVIDENCE 的一句**（"本仓实际没有任何 recover 生效"）⇒ **以本 §2 为准**。
- ★ 另：T35 复核里 **"panic 的后果面"** 那一项的结论**不受影响** —— 我当时的三条证据里，真正支撑"启动期 panic 不会被吞"的是前两条（`main.go` 无 defer/recover、`initialize.Gorm()` 唯一调用方是 `main.go:26` 纯启动路径）；第三条（唯一的 recover 是未注册的 Gin 中间件）**本就只是补强**，现被替换为"gin 内置 Recovery **只管请求期**、**不在启动期**" ⇒ **结论同向且更强**。
