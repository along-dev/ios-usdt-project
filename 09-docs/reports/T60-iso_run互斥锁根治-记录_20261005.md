## 2 · 修法（`AD-03` **方案 A**）

```python
def _takeover_stale_lock():
    """把**陈旧**锁**原子搬走** —— os.replace（改名）原子且目标唯一 ⇒ 只有一个进程搬得动；
       ⛔ 不用 os.remove ＋ open("w")（那正是 TOCTOU 漏洞所在）。"""
    dst = "%s.stale.%d" % (LOCK, os.getpid())
    try:
        os.replace(LOCK, dst)
    except OSError:
        return False
    try:
        os.remove(dst)
    except OSError:
        pass
    return True

def acquire_lock(max_tries=3):
    for _ in range(max_tries):
        try:
            fd = os.open(LOCK, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o644)   # ★ 内核级原子"不存在则创建"
        except FileExistsError:
            old = <读锁内 PID>
            if old.isdigit() and _pid_alive(int(old)):
                raise RuntimeError("★ 拒绝并发：…")            # ★ 活持有者 ⇒ 拒绝（V3）
            _takeover_stale_lock()                              # ★ 陈旧 ⇒ 原子搬走（V2），再重抢
            continue
        os.write(fd, str(os.getpid()).encode("ascii")); os.close(fd); return
    raise RuntimeError("★ 锁竞争：重试 %d 次仍失败（疑似多条线同时抢）")
```

★ **死锁自愈保留**（`F-09` 的"锁卡死"兜底不回潮）：抢输后仍判持有者死活，死则**原子搬走**再重抢。
★ `release_lock()` **未改**（它只在 `old == str(os.getpid())` 时删 ⇒ 不会误删别人的锁）。
★ `main()` 的调用点 `acquire_lock()` **未改**（新签名有默认值 ⇒ 兼容）。
