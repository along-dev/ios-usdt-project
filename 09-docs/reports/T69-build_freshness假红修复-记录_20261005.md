## 2 · 根因与修法

**根因（★ 我实测复现，非转述）**：`proc_info` 把 `Get-Process` 的 `Path` **经 `ConvertTo-Json` 直接写到控制台**，而本机控制台编码是 **GBK（cp936）** ⇒ 路径里的 **`漏洞` 被毁成 `©??`**：

```
改前实测：E:\ios©��\_integration\_fix_work\_i2c1_server.exe     ← 漏洞 被毁
         ⇒ os.path.isfile() = False ⇒ F2「无法取得二进制路径（进程信息不可读）」⇒ F3 SKIP
         ⇒ RESULT=RED（★ 本机<任何> Go 卡收口恒红 ⇒ 恒红＝没有检查）
```

**修法（★ 精确 diff 只落两处）**：`proc_info` 内

```powershell
# 改前：$o = [ordered]@{ path = $p.Path; start = … }
# 改后：
$pb = $null; if ($p.Path) { $pb = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($p.Path)) }
$st = $null; if ($p.StartTime) { $st = $p.StartTime.ToString('o') }
$o = [ordered]@{ path_b64 = $pb; start = $st }
```
Python 侧：`path = base64.b64decode(pb).decode("utf-8", "replace") if pb else j.get("path")`

★ **为什么用 Base64 而不是 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`**：★ 后者**依赖 PowerShell 的输出编码设置真的生效**（受调用方式/宿主影响）；★ **Base64 让 JSON 里<根本没有非 ASCII 字节>** ⇒ **编码问题被从根上取消**（不赌 cp936/utf-8 猜得对）。卡 §二 的「**显式 UTF-8 读**」以这种**免疫**形式落地。
★ **改动范围**：`diff -u 改前 改后` ⇒ **只有 `+import base64` 与 `proc_info`（docstring ＋ PS 串 ＋ 解码）**；★ **`F1`/`F4`–`F6` 的代码路径<一字未动>** ✓
