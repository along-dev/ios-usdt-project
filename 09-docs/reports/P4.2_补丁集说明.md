## 关键设计决策（附理由）

### 1. `collect.mode` 复用字典表，默认 `gasleak`

> **★ 实测更正**：我最初按 gin-vue-admin 惯例假设存在 `sys_params` 表，
> **实际不存在**——本库 27 张表全部核对过，无任何 `*params*`/`*config*` 表。
> gin-vue-admin 的真实键值存储是 **`sys_dictionaries` + `sys_dictionary_details`**。
> 迁移脚本与 `collectMode()` 已同步改为读字典表。

- **不新建表**：复用现有字典表，`type='collect_mode'`，取 `status=1` 的 `value`
- **⚠ 实测修正**：`sys_dictionary_details.value` 是 **`bigint(20)`（数值型）**，
  **不能存字符串** `'gasleak'`（首次执行报 `ERROR 1366`）。
  故按该表原生设计：**`value` 存数值码，`label` 存可读名**
  （`1=gasleak` / `2=qianke` / `3=both`），Go 侧映射回字符串
- **默认 `gasleak`**：一期主体是 gasleak 三链 + 地址池；默认 `qianke` 会让 gasleak 白跑
- **读不到时也返回 `gasleak`**：`collectMode()` 的兜底与迁移默认值一致，
  保证"开关缺失"时走**安全的互斥分支**，而不是静默允许双重归集

### 2. `collect-result` 只记账，不转账

潜客 `blockchain.Sk()` **同时做链上转账与分账**，与 gasleak collect 并行会
**双重归集**。因此：

- gasleak 负责链上动作 → 回传结果 → 潜客**仅按 `Sk()` 的比例口径落 bill**
- `collect-result` 的金额列用 `bill.total_num`/`num`/`usdt_num`
  （**`bill` 无 `amount` 列**）

### 3. 幂等靠 DB 唯一索引兜底

`collect-result` 先查 `transfer_hash` 再插，但**并发下先查后插会重复**，
故加 `uk_transfer_hash` 唯一索引。
⚠ **建索引前必须检查存量重复**（脚本注释里有查询语句）。

### 4. 隐藏菜单是数据操作，不是前端补丁

实测 `src/pinia/modules/router.js` L52-53：

```javascript
const asyncRouterRes = await asyncMenu()
const asyncRouter = asyncRouterRes.data.menus
```

菜单**全部来自后端** `sys_base_menus`，前端只硬编码了 `404`/`reload`。
→ 因此 `20-hide-scaffold-menus.sql` 改数据库，**不需要改 Vue 代码**。

### 5. `Sk()` 保留，不删

`ShouGe` → `Sk()` 是**唯一支持 bsc 链**的归集路径
（gasleak `derived-address.chain` 枚举为 `['eth','tron','btc']`，**不含 bsc**）。
互斥只是"默认不让它跑"，不是删除能力。

## 端到端验证步骤

### V1 迁移生效

```sql
SHOW COLUMNS FROM `machine` LIKE 'platform';
SHOW COLUMNS FROM `machine` LIKE 'ios_version';
SHOW COLUMNS FROM `wallet`  LIKE 'btc_%';           -- 期望 2 行
SHOW INDEX  FROM `bill` WHERE Key_name='uk_transfer_hash';
SELECT d.`id`, d.`type`, dd.`value`
  FROM `sys_dictionaries` d
  LEFT JOIN `sys_dictionary_details` dd ON dd.`sys_dictionary_id`=d.`id`
 WHERE d.`type`='collect_mode';
```

### V2 归集回传幂等

```bash
# 首次
curl -X POST http://<host>/app/collect-result \
  -H "access-token: $T" -H "Content-Type: application/json" \
  -d '{"wallet_id":15,"chain":"eth","tx_hash":"0xTEST1","amount":"1.5",
       "to_address":"0x1","collected_at":1708592661842}'
# 期望: code=0, duplicated=false

# 重复（同 tx_hash）
# 期望: code=0, duplicated=true，且 bill 表【不新增行】
```

```sql
SELECT COUNT(*) FROM `bill` WHERE `transfer_hash`='0xTEST1';   -- 期望 1
```

### V3 归集互斥

| 场景 | 期望 |
|---|---|
| `collect.mode=gasleak` → 点"收割" | 返回"当前归集方为 gasleak，请勿手动收割"，**不产生 bill** |
| gasleak collect 遇到 `progress=1` 的钱包 | 日志 `skip collect: qianke is collecting`，**跳过** |
| 潜客 API 不可达 | gasleak **保守跳过**（宁可漏收，不双重归集） |

### V4 脚手架菜单隐藏

- 登录后台 → 左侧**看不到** `关于我们`/`示例`/`系统工具`/gin-vue-admin 外链
- 业务菜单（首页/资源管理/地址管理/财务管理/系统配置/代理列表）**不受影响**

### V5 BTC 列可落

```sql
-- 同步一笔 chain=btc 的 derived-address 后
SELECT `id`, `btc_address`, `btc_private_key` FROM `wallet` WHERE `btc_address` <> '';
```
