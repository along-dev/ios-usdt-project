## 四 · ★★ 我在自测里抓到的**自己三处 bug**（如实留痕；★ 均由**判据自身**抓出）

1. **`AD09_TMP_DB` 起错名** ⇒ 装置**模块级护栏**（要求形如 `qk_ad09_*`）**当场拒载** ⇒ `rc=1` ⇒ 我据此把探针库名改成 **`qk_ad09_t56`** ✓（★ 顺带**正面确认**：该护栏**有效**、是 fail-closed ✓）
2. ★★ **`--device` 形同虚设**：原来把"`device` 所在**目录**"塞进 `sys.path` 再按**规范模块名** import ⇒ 若被指的件**用了别的文件名**，`import_module` 会**从 cwd 里 import 到<ins>原件</ins>** ⇒ **两种变异给出完全相同的结果**（V2 当场照出 ✗，我一度以为"变异无效"，实为**①我判据件的 bug**）⇒ **修法：先把 `--device` 指的件<ins>复制成规范名</ins>再加载** ✓
3. ★★ **两处假阴性**（都会让本件**漏报**）：
   - **变体库未在"产出跑"前清掉** ⇒ 原件跑建出的 `dd3/dd4` 仍在 ⇒ 产出跑再 `CREATE` 撞"已存在"报错 ⇒ 新增＝[] ⇒ **看着"安全"** ✗（`★D5` 一度被漏）
   - **只测"有没有建/删库"，没测"产出是否<ins>可执行</ins>"** ⇒ `★D6` 的产出 `DO 0 DATABASE …` **语法错、根本没跑** ⇒ 也"看着安全" ✗
   ⇒ **修法**：① `reset_probe()` 把各变体库**一并清**；② 增设**第三把尺**：产出**必须可执行**（且用**同名量对照**——只在「**原件不报错、产出报错**」时才算畸形，⛔ 否则会把"无默认库下本就 1046"这类**量尺自身的产物**误判成装置缺陷 ✗）

★ **这三处都不是装置的缺陷，是我判据件的缺陷** ⇒ ★ 而**它们是被 V2／自测抓出来的** ⇒ 说明**"反向自证"与"自检"不是形式主义** ✓
