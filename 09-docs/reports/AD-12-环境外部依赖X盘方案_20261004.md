## 1 · ★ 关键前提：为什么当初会用 `X:`（**决定了方案方向**）

`_fix_work\start_i2c1_services.ps1:32-40` 原文（**逐字**）：

```
# ★★ 根治中文路径编码事故（2026-09-29 实测）：
#    本机 WMI/Win32 API 与外部 exe 交互时，'E:\ios漏洞' 会被错误解码为
#    'E:\ios婕忔礊' ⇒ mysqld 报 "Can't change dir to ..."（Errcode 2）而启动失败，
#    进而 Go 连不上 DB ⇒ global.GVA_DB 为 nil ⇒ LoadRpcList panic。
#    解法：用 subst 把中文路径映射为纯 ASCII 盘符 X:，所有服务一律走 X:。
```

⇒ **`X:` 的成因是「中文路径 (`ios漏洞`) ＋ WMI/Win32 交互的编码缺陷」，不是随手用的临时路径。**
⇒ **因此本方案的判据必须是**：换掉 `X:` 的同时**不能把 `E:\ios漏洞` 这个中文路径重新交给同样的 WMI 交互路径**，否则等于回退到事故现场。

★ **一处内部矛盾（如实登记）**：`restore_services.ps1` 已把主路径改为 `$REAL_X = 'E:\ios漏洞\_integration\_fix_work'`（**中文路径**），与 `start_i2c1_services.ps1` 注释所述的隐患**假设相反**。两者目前并存而服务是起的（六端口 UP），说明**该编码缺陷至少在 `restore_services.ps1` 走过的路径上未复现** —— 但**没有人为这件事做过判据**（见 §6 未验证）。

## 4 · 失败形状：`X:` 消失时**响亮还是静默**

| 处 | 形状 | 依据 |
|---|---|---|
| **`--env-file-if-exists=X:\…\_ad3001.env`**（`_ad_start_3001.ps1:6`） | ★★ **静默（最危险）** | **flag 名即语义**：`--env-file-if-exists` **文件不存在就跳过、不报错** ⇒ Node 以**默认配置**启动（错端口/错库/错路径）而**无人察觉**。★ 该语义由 flag 名与 Node 官方行为推定，**未实测**（见 §6） |
| **`LOG_DIR=X:\…\_i1c3_logs`**（4 个 env ＋ `DEPLOY.md:196`） | ★ **静默**（有 INFO，不阻断） | **盘上历史证据**：`_fix_work\_svc_n4.out:10` / `_n8.out:10` / `_r_n.out:10` 逐字为 `INFO Log directory not found, skipping cleanup {"logDir":"X:\\…\\_i1c3_logs"}` ⇒ 服务**继续跑** |
| `STORAGE_ROOT=X:\…` | **未判定** | 取决于各服务的实现；**本轮未读实现**（见 §6） |
| `MYSQL = r"X:\…\mysql.exe"`（`run_regression_v2.py`、`verify_doc_code_parity.py`） | **响亮** | `subprocess` 找不到可执行文件 ⇒ 抛异常/非零退出 |
| `Set-Location 'X:\…'`（`_runjudge2.ps1:2`、`_runjudge_w1c1b.ps1:4`） | **半静默** | 目录不存在 ⇒ PowerShell 报错；但脚本 `$ErrorActionPreference` 若为 `Continue` 则**继续往下跑** ⇒ 后续全在错误 cwd 上操作 |
| `_ad_audit_cache.mjs:12` / `_ad_d01_verify.mjs:7` / `_ad_landingext_delta.mjs:79` | **响亮**（文件操作/子进程缺件） | 由 API 语义推定，**未实测** |
| **C1/C2/C3 的 `Test-Path` 守卫** | ★ **响亮且自愈** | 它们**先检测再 `subst`** ⇒ `X:` 不在时**自己建好**，不失败 |

⇒ **规律**：**凡走 `Test-Path` 守卫的（subst 创建侧）都是响亮的；凡把 `X:` 写进 env/参数交给别人解释的（消费侧）都可能静默。**
★ 与本机已有前例一致（后台任务/子进程看不到 `X:` ⇒ 零输出/找不到文件）。

## 5 · 改法与风险（逐处）

### 5.1 ★ 首选：**不恢复中文路径，而是换一个"稳定的 ASCII 路径"**（避开 §1 的成因）

| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| **① 真实 ASCII 目录 ＋ junction** | 建 `E:\usdt`（纯 ASCII），`mklink /J E:\usdt E:\ios漏洞` ⇒ 所有启动参数写 **`E:\usdt\…`** | **不依赖 subst（持久）**、**绕开中文**、**不需改目录布局**。风险：junction 需一次创建（属**触部署**）；`E:\usdt` 与 `E:\ios漏洞` 是**同一份数据**，误删 junction 不等于删数据（`mklink /J` 删除只删链接）—— 但**必须验证**这一点对本机为真 |
| **② 换成另一个真实盘符** | 若本机有第二个盘（如 `D:`），把 `_fix_work` 放过去 | 需**搬动 906 件判据** ⇒ churn 极大（与 AD-02 的取舍同因，**不推荐**） |
| **③ 直接改回 `E:\ios漏洞`（中文）** | 照 `restore_services.ps1` 现状做 | ⚠️ **风险最高**：等于把中文路径重新交给 §1 所述的 WMI/Win32 交互。⇒ **只有在 §6-① 那条判据跑绿之后**才可考虑 |

⇒ **推荐 ①**：**ASCII 且持久**，同时满足"绕开编码事故"与"不依赖会话级 subst"。
