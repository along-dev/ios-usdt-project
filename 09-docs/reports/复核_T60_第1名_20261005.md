## 三 · ★★ 击穿机制（★ 定向复现，非推理）

**根因：`O_CREAT|O_EXCL` 创建出的是<ins>空文件</ins>，而"陈旧"是从<ins>文件内容</ins>推断的；`os.open` 与 `os.write(PID)` 之间存在窗口。**

`acquire_lock`（受审件 `:268-286`）的时序：
```
A: os.open(LOCK, O_CREAT|O_EXCL)   ← 文件此刻**已存在、内容为空**
   … 尚未 os.write(PID) …
B: os.open(...) → FileExistsError
   读 LOCK ⇒ old = ""            ← 空串
   old.isdigit() 为假 ⇒ 不判"活持有者"
   _takeover_stale_lock()        ← os.replace 把 **A 的锁**搬走
   B 重抢 ⇒ 成功
⇒ **A 与 B 同时持锁**（A 从头到尾没意识到锁被搬走）
```
★ **定向复现**（脚本 `_T60_review_20261005/t60_probe.py`）：造一个**空锁文件**（＝另一进程正处于 create→write 之间），调 `acquire_lock()` ⇒ ★★ **接管成功**（`probe_new.out` ①）。★ **改前件同一探针也接管成功** —— 说明该窗口**改前即有**，但 ★ 改前的抢锁路径本就整体非原子（20/20 全破），此窗口被掩盖；**改后**它成了**唯一**残留破口。
★ **第二条（静态）**：`_takeover_stale_lock()` 搬走的是"**当下在 `LOCK` 上的东西**"，**<ins>不复核</ins>**它是否还是刚才读到的那把陈旧锁 ⇒ **检查与搬走不原子** ⇒ 在"读到陈旧 PID"与"`os.replace`"之间，别的进程可能已**建好新锁**，于是**新锁被搬走** ⇒ 同样双双持锁。

## 十 · Findings（10 字段）

### `F-T60-A1`（**P1 · 阻断** · 本卡目标未达成）—— 互斥**未根治**：空锁（create→write 之间）被判"陈旧"并被接管 ⇒ 仍可**同时持锁**
- **位置**：`iso_run.py:268-286`（`acquire_lock`）＋ `:239-252`（`_takeover_stale_lock`）
- **现象**：自研量尺在**卡自身配置** N=4 上得 **2/20、3/20** 轮重叠；**N=8 ⇒ 17/20**、最大同时 **6**。执行方声称 `0/20` 恒 1 ⇒ **不可复现**。
- **机制**：`O_CREAT|O_EXCL` 造出**空文件**；失败方读得 `""` ⇒ `isdigit()` 假 ⇒ 判非活持有者 ⇒ `os.replace` **搬走那把刚建、尚未来得及写 PID 的活锁** ⇒ 两进程同持。
- **复现**：`t60_probe.py` ①：预置**空锁** ⇒ `acquire_lock()` **接管成功**（应拒绝或重试）。
- **失败场景（接原始危害）**：两 `iso_run` 同跑 ⇒ 同实例同库、同 `tx_hash` 1ms 内各打一次 ⇒ 撞 `uk_txhash_role` ⇒ 落败方 `code=7` 而赢家已提交 ⇒ ★ **`code=7` 却 `bill=3` 的自相矛盾假红**（＝本卡**存在的原因**）。
- **建议方向**（⛔ 不代改）：① **原子"带内容创建"** —— 先写临时文件再 `os.replace` 入位，并把"**内容不可解析/为空**"**fail-closed 视为活锁**（或短暂重试），⛔ 不判陈旧；② `_takeover_stale_lock` **搬走前后复核**（搬走的必须仍是那把陈旧锁；或改用"**带持有者令牌**的锁"）。
- **严重度理由**：卡**唯一目的**就是消除该假红；现仍可复现 ⇒ **阻断**。

### `F-T60-A2`（**P3**）—— `release_lock()` 非原子，可能删掉**他人**的锁
- **位置**：`iso_run.py:289-296`；**现象**：`exists → open().read() → os.remove` 三步非原子。
- **前提**：需"本进程被判死"（`_pid_alive` 误判）才会出现他人接管窗口 ⇒ 低概率。
