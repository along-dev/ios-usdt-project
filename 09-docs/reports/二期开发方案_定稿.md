## 四 · ★★★ 二期开工前的 5 项裁决（**已定案**）

### 裁决 1：**`06-android` / `11-payment` = 【交付物】+ 补 README**

**★ 调度取证**：

| 目录 | 内容 | 定性 |
|---|---|---|
| **`11-payment`** | **36 `.py` + 16 `.js` + 15 `.json` + 2 `.wasm` + 4 `.bin` + 1 `.docx`** | ★ **项目外目标的侦察/验证产物** |
| **`06-android`** | **10 `.apk` + 5 `.py` + 3 `.txt` + 1 `.md`** | ★ **需求 §3.1 #1.7 的验收载体** |

**★ 关键发现：`11-payment/README.md` 已声明性质**（**D4-C4 所建**）：
> **本目录登记支付相关侦察/验证产物及其【定性与处置依据】。**
> **所有结论均为【项目外目标】的测试结果，【不构成本项目自身的安全保证】。**

**⇒ 裁决：两者均为【交付物】**，**理由**：
1. **`06-android`** 是 **需求 §3.1 #1.7（Android 三段链）的验收项**
2. **`11-payment`** 已有 README 声明性质
3. **两者均不在 `_manifest.sha256`** ⇒ 本就非"产物指纹"范围
4. **移出会破坏 §1.7 验收 + R3-C1 的已审结论**

**★ 执行要求**：
- ★ **`06-android` 补 README**（**目前无**），**明确定性与处置依据**
- ★ **`11-payment/README.md` 补充**"本目录为交付物"的声明

### 裁决 2：**R-01 修**（定义"一个 machine 对应哪个 custom"）

**★ 裁决：修** —— **理由**：
**多客户库中分成落到无关客户 = 资金错误** ⇒ **属 P1**。

**做法**：`ResolveWalletId` 在 `device_id` 唯一时**必须**解析出 machine 的归属 custom，
**与传入的 custom 比对**；**不一致 ⇒ 拒绝**。

### 裁决 3：**A1 先做灰度判定**（**不直接改表**）

**★ 裁决：做灰度判定** —— **理由**：
文档 `:242` 明写**「17.3–18.3 不值得按补偏移表投入」**，
且**累积语义 ⇒ 改表会影响所有 ≥ 该版本**。

### 裁决 4：**C4 只删 `example/` + `systemTools/`**

**★ 裁决** —— **理由**：
- **`example/` / `systemTools/`** 是**脚手架演示**（**gin-vue-admin 模板自带**）
- **`about/` / `superAdmin/`** **可能被菜单/路由引用** ⇒ **保留并标注**

**★ 前置**：**删前须全树搜引用**（**P-8：改错一份等于没改**）。

### 裁决 5：**F8（TTL）优先于 F9（多副本）**

**★ 裁决** —— **理由**：
- **F8（TTL 未纳入设计）** ⇒ **凭证超期静默消失** ⇒ **直接影响资金**
- **F9（多副本域切换）** ⇒ **D3-C1 已用行锁缓解** ⇒ **降级**
