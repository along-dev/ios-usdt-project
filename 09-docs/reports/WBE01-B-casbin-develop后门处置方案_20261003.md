## 一 · 事实与影响面（**全仓实测，不缩窄路径**）

### 1.1 后门本体

```go
// 01-backend-go/middleware/casbin_rbac.go:27
if global.GVA_CONFIG.System.Env == "develop" || success {
    c.Next()
} else {
    response.FailWithDetailed(gin.H{}, "权限不足", c)
    c.Abort()
    return
}
```
⇒ `System.Env == "develop"` 时**无条件放行**，`success`（casbin 判定结果）**被短路**。

### 1.2 影响面：**单点、自包含**（全仓、两种写法、不限目录）

```
$ grep -rn '"develop"' --include=*.go .        # 全仓，未加任何目录参数

$ grep -rn '"develop"' --include=*.js --include=*.vue 03-web-admin/src 02-backend-node/src_restored

```
⇒ **全仓只有这一处**读取 `System.Env`、只有这一处比较 `"develop"`；前端/Node 无依赖。
⇒ **移除该旁路不会牵动任何其他代码**；反之，移除后 `System.Env` 在**本仓内成为无人读取的配置项**（配置件在仓库外 `_i2c1_ws/config.yaml`，留着无害，但**建议在件里注明它已不再影响鉴权**）。

### 1.3 为什么这是"埋雷"（三条，逐条可复现）

1. **触发条件极易被误设**：`Env` 是**部署期可控**的字符串，且语义模糊（"跑在开发机"）。
2. **后果是静默的**：绕过**不报错、不打日志**，服务照常起。
3. ★ **它会让本线的判据全部变假绿**：R3 反向组（`/device/list`、`shougei`、`copy_private`… 期望 `code:7`）
   在 `Env=develop` 下会**全部返回 `code:0`** —— 即**给出绿灯的是一个被绕过的检查**。
   （本线已实证：当前 `config.yaml` 是 `production` ⇒ **旁路未生效**，R3 反向组因此为真。这条前提已写进 `三级等级设计接线记录_…_代理商级.md`。）

### 1.4 ★ 一条必须先说清的执行约束：**改源码 ≠ 生效**

运行中的 8888 由**树外二进制** `E:\ios漏洞\_integration\_fix_work\_i2c1_server.exe` 提供（本轮实测 PID 6648；项目已知陷阱："**改源码不重编译＝没改**"）。
⇒ 本卡改的是源码；**要看到效果必须重编译并换二进制**（会重启共享 8888，影响所有并行线）。
⇒ **这一点直接决定 §三 的反向断言怎么跑**（见 3.2）。

## 二 · 修法候选与结论

> **选型的第一原则（采纳调度给的核心理由）**：**权限旁路不允许由"环境名"隐式触发** —— `Env` 常被当作"跑在开发机"的泛指，把它与"跳过鉴权"绑在一起，等于**把安全开关交给一个语义模糊的变量**。

| 候选 | 内容 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **（甲）直接去掉** | 删掉 `Env == "develop" \|\|`，只留 `if success` | **最干净**；风险面归零；全仓单点、无依赖（§1.2） | 失去开发期免 seed 的便利 | ✅ **可接受**（见下"开发期怎么办"） |
| **（乙）改成显式开关** | `GVA_CASBIN_BYPASS=1` 且**启动告警 + 每次放行记日志** | 保留便利；显式、可审计 | **仍是一条真旁路**；开关本身可被误设 | ✅ **可接受，但需加固**（见丙） |
| **（丙）显式开关 ＋ 环境双条件（推荐）** | `GVA_CASBIN_BYPASS=1` **且** `System.Env != "production"` **才**放行；启动打**高声告警**；每次放行**记 WARN 日志（含 path/method/authorityId）** | 保留便利；**双重条件** ⇒ 即使开关被误设，**生产仍不会被绕过**；旁路**可审计** | 代码量略多 | ★ **本线推荐** |
| （丁）其它 | 例如"仅在二进制带 build tag 时启用" | — | 改动面更大、收益不明确 | 否 |

### 2.1 推荐 **(丙)**，理由三条

1. **把"隐式"变"显式"**：触发条件从"环境名叫 develop"（模糊）变成"**明确设了 `GVA_CASBIN_BYPASS=1`**"（清晰）。
2. **加第二重保险**：**`Env != production` 是硬条件** ⇒ 生产环境下**任何误设都无法绕过**。
   （纯 (乙) 没有这重保险：一个 `GVA_CASBIN_BYPASS=1` 就能在生产绕过。）
3. **可审计**：启动告警 + 每次放行记 WARN ⇒ 旁路**在使用中会被看见**，而不是静默。

★ **若你认为"便利不值得留一条旁路"，(甲) 同样可接受**（两条我都能论证；差别只在"开发期便利"这一项）。**最终选哪条，请你裁。**

### 2.2 开发期怎么办（调度点名要答）

| 场景 | (甲) 下怎么办 | (丙) 下怎么办 |
|---|---|---|
| 新加端点、casbin 无规则 ⇒ 403 | 给开发环境的 authority **seed 一条"全放行"策略**（如给 `888` 或一个 `dev` authority 批量加 `/*`），**放在 DB 而非代码里** —— 好处：**策略可见、可撤、不影响生产逻辑** | 同 (甲)；或临时 `GVA_CASBIN_BYPASS=1`（**默认关**，且非 production 才生效） |
| 想在本地完全跳过 | 同上（DB seed） | 同上 |
★ **注意**：(甲) 的"DB seed 全放行策略"会把风险**从代码搬到数据** —— 但它**可被审计（一条 SQL 就看得到）**，且**不会因为部署时写错一个环境名而静默发生**。⇒ 这是 (甲) 可接受的关键理由。

## 三 · 反向断言设计（调度要求"必须出读数"）

### 3.1 断言清单

| # | 条件 | 操作 | 期望 |
|---|---|---|---|
| **R-A** | **`Env=develop`（或旁路开启）** | 用**未授权 authority 的会话**调受保护端点（如 `1234` 调 `/device/list`） | **HTTP 200 + body `code:7`（权限不足）** —— ★ 按契约 **C-2：别看 HTTP 状态码** |
| **R-B（正控）** | `Env=production`，旁路关 | 用**已授权**会话调同端点（如 `888` 调 `/device/list`） | `code:0` |
| **R-C（负控）** | `Env=production`，旁路关 | 未授权会话调同端点 | `code:7` |
| **R-D（新）** | **旁路被启用时** | 观察启动输出与运行日志 | **有高声告警**；每次放行**有 WARN 行**（含 path/method/authorityId）—— 仅 (乙)/(丙) 适用 |
| **R-E（新）** | **生产 + 误设开关** | `Env=production` 且 `GVA_CASBIN_BYPASS=1` | **仍返回 `code:7`** ⇒ 证明 (丙) 的双条件生效 |

### 3.2 ★ 怎么跑出 R-A：**两个方案，我推荐 (a)**

**问题**：R-A 需要"**`Env=develop` ＋ 新代码**"的实例。而 (§1.4) 运行中的 8888 是**树外旧二进制** ⇒ 直接打它**测的是旧代码**，无意义。

| 方案 | 做法 | 优 | 劣 |
|---|---|---|---|
| **(a) 隔离实例 ★推荐** | **另起一个 Go 实例**：用**独立端口**（如 8899）＋ **独立 config**（`env: develop`，其余同现状）＋ **同一个 DB**；打完即停 | **不动共享 8888**；可自由反复跑；R-A/R-E 都能真跑 | 需一次 Go 构建（**冷 cache 约 30 分钟**，热 cache 数分钟）＋ 一个空端口 |
| (b) 换共享二进制 | 重编译 → 替换 `_i2c1_server.exe` → 重启 8888 | 直接 | **打断所有并行线**；且为跑一条断言而重启生产式实例，代价远大于收益 | ✗ |

⇒ **本卡的反向断言按 (a) 执行**：起 8899（develop 配置）→ 跑 R-A → 停；再起 8899（production 配置）跑 R-B/R-C/R-E。
★ **会在动工前先报调度**：占用 8899、临时 config 路径、构建耗时（因 P-38/共享资源，我不想擅自占端口）。

### 3.3 断言会话怎么来（复用本线已有能力）

沿用 `_fix_work/rbac_login.py` 的**自签 JWT**（免登录，绕过内存验证码 —— 本线已实证该路径可行）。
⇒ R-A/R-B/R-C/R-E 都用**同一套 token 铸造**，authority 分别取 `1234`（未授权）与 `888`（已授权）。
