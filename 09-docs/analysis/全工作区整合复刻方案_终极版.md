## 第四部分：关键技术细节（本轮全量核实）

### 4.1 iOS 载荷结构（coruna/payloads）

`manifest.json` 定义 **20 组 × 8 种 type**：

| type | 含义 | 文件形态 | f1 段基址 |
|---|---|---|---|
| `0x05` | shellcode | `.bin`(24 KB) | `0x050000` |
| `0x07` | 元数据/配置 | `.bin`(49/468 B) | `0x070000`/`0x070005` |
| `0x08` | **主 dylib** | Mach-O thin(196-228 KB) | `0x080000` |
| `0x09` | 辅助 dylib | Mach-O thin(263-333 KB) | `0x090000` |
| `0x0a` | 变体 dylib | Mach-O thin / `.bin` | `0x0a0000-2` |
| `0x0f` | **持久化 dylib** | Mach-O thin(191 KB) | `0x0f0000` |

**dylib 归属**（`implant_ops.js` 确认）：

```
entry0_type0x08.dylib → IOPMrootDomain 注入
entry2_type0x0f.dylib → com.apple.xpc.launchd 持久化
bootstrap.dylib       → JavaScriptCore.framework 注入
```

### 4.2 F00DBEEF 容器格式（已完整还原）

`payload_cdn.py` 给出构造与校验：

```
Header:      uint32 magic(0xF00DBEEF) + uint32 entry_count
EntryTable:  N × (uint32 f1, uint32 f2, uint32 data_offset, uint32 data_size)
Data:        各 entry 数据拼接
```

`Stage3_VariantB.js` 的 `buildContainer()` 与之对应。

### 4.3 Android 三段加载链（已完整脱壳）

**第 1 层**（`strip.apk` 外层，`recon/apk/unpack.py` 已实现）：

```
[24B 头][int32 BE 长度][数据]
b=(b-199)&FF; b=(b*57)&FF; b=ror8(b,3); b=ror8(b,2)
k=((i*189+203+(i>>7))^232)&FF; b=(b-k)&FF; b=(b*237)&FF; b^=57; b=(b*243)&FF
→ GZIP
```

产出：`azjgiGhXOE`(8.7 MB DEX) + `taEtClxrsxC`(7.75 MB 文件包)

**第 2 层**（`b.apk` 的 `go0bxm7p04()`）：

```
key = <32B 载荷密钥 · 见 06-android/tools/_payload_key.py>
mode = AES/CTR/NoPadding
iv = asset[0:16]; ct = asset[16:]
```

产出：`b.apk`(7.75 MB 真实载荷) + 30+ 资产（含 `1.bt/2.bt/3.bt`）

**第 3 层**（`0gvw74arcr5sml`）：L3 算法 = `AES/CBC/PKCS5Padding` + `SHA256((A⊕B)‖salt)`

**免落盘机制**：`iwoscwla()` 反射 `ActivityThread.currentActivityThread → mPackages → mClassLoader`，把内存 DEX 注入 Application 类加载器。
