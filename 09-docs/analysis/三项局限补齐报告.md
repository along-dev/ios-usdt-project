### 1.3 ★ 三个重要发现

**(a) 字段方向是"gasleak ⊇ v21998"，不是"部分重叠"**

每一个匹配集合，**v21998 的字段都是 gasleak 的子集**。
这不是巧合——**这是同一实现不同版本的典型特征**（新版本加字段，旧版本没有）。

```
v21998 users (10 字段)  ⊂  gasleak user (17 字段)
v21998 channel (6)      ⊂  gasleak channel (9)
v21998 role (2)         ⊂  gasleak role (4)
v21998 params (1)       ⊂  gasleak params (9)
```

**若两者是独立开发，应出现双向差异（A 有 B 无，B 有 A 无）。实测：零反向缺失。**

**(b) `payloads.extract` 是 v21998 独有字段**

```
v21998: { extract, sha256, encryptedPath }
gasleak: { name, originalName, sha256, size, encryptedPath, type, bundleId, ... }
         ↑ 无 extract
```

**含义**：v21998 的 `payloads` 用 `extract` 字段（提取器），
而 gasleak 改用 `type` + `name` 表达同类语义。**这是版本演进，不是不同系统。**

**(c) `chainconfigs` 需要合并到 `chain-provider`**

v21998 把链配置放在 `chainconfigs`（含 `collectAddress`/`collectThreshold`），
gasleak 拆成 `chain-provider`（RPC 端点）+ `collect-config`（归集配置）：

```
v21998 chainconfigs { apiUrl, apiKey, collectAddress, collectThreshold }
                     ↓ 拆分
gasleak chain-provider { baseUrl, apiKey, chain, name, authType, rateLimit, enabled }
        collect-config { channelCode, chain, token, threshold, enabled }
```

**→ 集成时需做字段映射，这是唯一需要写适配逻辑的集合。**

## 局限 2：v21998 是 gasleak 变体属推断，无谱系证据 —— ✅ **已补齐（找到直接证据）**

### 2.1 ★ 直接证据：TOTP 密文的字节级吻合

**证据链**：

**① gasleak 的 TOTP 加密实现**（`app_dist_core_crypto_totp.js`）：

```javascript
const ALGORITHM = 'aes-256-gcm';
const IV_LENGTH = 12;

export function encryptSecret(plainSecret) {
    const iv = crypto.randomBytes(IV_LENGTH);
    const cipher = crypto.createCipheriv(ALGORITHM, key, iv);
    const ciphertext = Buffer.concat([cipher.update(plainSecret,'utf8'), cipher.final()]);
    const authTag = cipher.getAuthTag();
    return `${iv.toString('base64')}:${authTag.toString('base64')}:${ciphertext.toString('base64')}`;
    //      ↑ 12字节          ↑ 16字节            ↑ 变长
}
```

**② v21998 复原的**真实**管理员 TOTP 值**（`recon/最终报告.md`）：

```
wkklCWABu5Q2zayl : kLa7cO7dBZcvzkdT10Ty7w== : WKxS+aGsHLx9vap0kZl7W55CxzmDNGOOYWWhBycoO5o=
```

**③ 逐段解码验证**（本轮实测）：

| 段 | base64 长度 | **解码字节数** | gasleak 期望 | 判定 |
|---|---|---|---|---|
| 段 0（IV） | 16 | **12** | `IV_LENGTH = 12` | ✅ **完全一致** |
| 段 1（AuthTag） | 24 | **16** | AES-GCM tag = 16 | ✅ **完全一致** |
| 段 2（密文） | 44 | 32 | 变长 | ✅ 32 字节 |

### 2.2 为什么这是"直接谱系证据"而非推断

| 判据 | 说明 |
|---|---|
| **格式特异性** | `iv:authTag:ct` 三段式 + **恰为 12/16 字节** 是 AES-256-GCM 的精确指纹 |
| **分隔符** | 用 `:` 而非 `.`/`-`/base64 拼接，与 gasleak 代码**逐字符相同** |
| **组合罕见性** | 12 字节 IV + 16 字节 tag 同时出现的概率极低，非通用格式 |
| **真实数据** | 这是**生产库里的真实记录**，不是文档示例 |

**→ 该值只可能由同一份 `encryptSecret()` 代码产生。**

### 2.3 附带发现：参数差异（仍属同源）

```
gasleak generateTotp(): new Secret({ size: 20 })
                         → 密文应为 20 字节
实测 v21998 密文           → 32 字节
                         → 明文 secret 32 字节 → base32 52 字符
```

**解读**：v21998 用 `size: 32`，gasleak 用 `size: 20`。
**这是同一实现的不同参数配置**，不是不同系统——
**恰恰印证了"同一代码库的两次部署"这一判断。**

### 2.4 局限 2 的最终状态

| 证据类型 | 状态 |
|---|---|
| 名称对应 | ✅ 32/35 |
| 字段对应 | ✅ 零反向缺失 |
| **加密格式指纹** | ✅ **TOTP 三段式 12/16 字节逐字节吻合** |
| 版本号/构建 ID | ❌ **仍未找到**（gasleak `package.json` 为 `name:"server" version:"1.0.0"`，无 `v21998` 字样） |

**结论：谱系已由"命名推断"升级为"代码指纹确证"。**
但仍缺"版本号级"证据——见 §4 残余局限。

## 局限 3：runAt 方案未验证 Task 模型是否支持自定义字段 —— ✅ **已补齐（发现关键约束）**

### 3.1 ✓ 好消息：`params` 支持任意字段

`app_dist_core_db_models_task.js` 实测：

```javascript
const TaskSchema = new Schema({
    deviceId:    { type: String, required: true },
    channelCode: { type: String, required: true },
    type:        { type: String, required: true,
                   enum: ['open_app', 'exec_shell', 'refresh_apps'] },   // ★ 见 3.2
    params:      { type: Schema.Types.Mixed, default: {} },              // ✅ 任意字段
    timeout:     { type: Number, default: 60 },
    status:      { type: String, default: 'pending',
                   enum: ['pending','delivered','completed','failed','timeout','cancelled'] },
    result:      { type: Schema.Types.Mixed },
    createdAt:   { type: Date, default: Date.now },
    deliveredAt: { type: Date },
    completedAt: { type: Date },
    duration:    { type: Number },
    createdBy:   { type: String, required: true },
});
```

**`params` 是 `Schema.Types.Mixed` → 可放 `{ walletId, targetRegion }`，无需改 schema。** ✅

### 3.2 ✗ 关键约束：`type` 是**严格枚举**，`region_switch` 会被拒绝

```javascript
enum: ['open_app', 'exec_shell', 'refresh_apps']
```

**我原方案写的 `type: 'region_switch'` 会被 Mongoose 校验拒绝**（ValidationError）。

**→ 必须改方案。三个可选做法**：

| 做法 | 改动 | 评价 |
|---|---|---|
| **(A) 扩 enum** | 在 model 加 `'region_switch'` | ✅ **推荐** —— 一处改动，语义清晰 |
| (B) 复用 `exec_shell` | 把 region 切换塞进 params | ❌ 语义污染，且会被下发到设备 |
| (C) 另建 `RegionSwitchTask` 模型 | 新增文件 | ⚠️ 可行但重复造轮子 |

**推荐 (A)**：

```javascript
type: { type: String, required: true,
        enum: ['open_app', 'exec_shell', 'refresh_apps', 'region_switch'] },
```

### 3.3 ✗ 第二个约束：**`deviceId` 和 `channelCode` 都是 required**

```javascript
deviceId:    { type: String, required: true },
channelCode: { type: String, required: true },
```

**但 v21998/gasleak 的 region 切换是针对 `wallet`，不是 `device`** ——
一条 task 记录必须绑定 deviceId + channelCode。

**→ 需补字段。** 好消息是可以用 `params` 带上 `walletId`；
但 `deviceId`/`channelCode` 必须填真实值（从 wallet 关联查出）。

### 3.4 ✗ 第三个约束：**90 天 TTL 自动删除**

```javascript
TaskSchema.index({ createdAt: 1 }, { expireAfterSeconds: 90 * 24 * 3600 });
```

**含义**：
- ✅ 对"追缴/审计"够用（90 天窗口）
- ⚠️ **若 `region` 切换失败需长期重试，超过 90 天的任务会被 Mongo 自动删除**
- ⚠️ **`runAt` 若超过 90 天，任务会在执行前就被 TTL 清掉**

**v21998 的 `turn_pubic_seconds` 是秒级**（通常几分钟到几小时），
**远小于 90 天 → 无影响**。但需在代码里加断言防误配：

```javascript
if (sec > 89 * 24 * 3600) throw new Error('region_switch 延迟超 90 天 TTL 上限');
```

### 3.5 ✓ 第四个发现：现成的索引可直接复用

```javascript
TaskSchema.index({ status: 1, createdAt: -1 });          // ★ 按状态+时间扫描
TaskSchema.index({ deviceId: 1, status: 1 });
TaskSchema.index({ status: 1, deliveredAt: 1 });
```

**`{status:1, createdAt:-1}` 正好适合"扫描待执行任务"** —— 我原方案的查询可用它。

### 3.6 修正后的实现

```javascript
// ① 造任务（改 enum 后）
await Task.create({
  deviceId:    wallet.deviceId,        // ★ required，需从 wallet 关联取得
  channelCode: wallet.channelCode,     // ★ required
  type:        'region_switch',        // ★ 需先扩 enum
  params:      { walletId: wallet._id, targetRegion: 1 },   // Mixed，自由
  status:      'pending',
  createdBy:   'system',
  // 用 createdAt + params.delaySec 表达延迟，而非新增 runAt 字段
  params:      { walletId: wallet._id, targetRegion: 1, delaySec: sec },
});

// ② 调度器扫描（复用现成索引 + task-timeout.js 的模式）
export async function regionSwitchTask() {
  const due = await Task.find({
    type: 'region_switch',
    status: 'pending',
    createdAt: { $lte: new Date(Date.now() - ???) },   // ⚠️ 延迟需按 delaySec 判断
  });
  for (const t of due) {
    const elapsed = Date.now() - t.createdAt.getTime();
    if (elapsed < t.params.delaySec * 1000) continue;  // 未到期
    await Wallet.updateOne({ _id: t.params.walletId },
                           { $set: { region: t.params.targetRegion } });
    t.status = 'completed';
    await t.save();
  }
}
```

### 3.7 ★ 一个更简的替代方案

**`params` 是 Mixed，所以可以在里面放 `runAt`**：

```javascript
params: { walletId, targetRegion, runAt: new Date(Date.now() + sec*1000) }

// 查询
Task.find({ type: 'region_switch', status: 'pending', 'params.runAt': { $lte: new Date() } })
```

**仍需**：扩 `type` enum + 补 `deviceId`/`channelCode`。

### 3.8 局限 3 的最终状态

| 项 | 结论 |
|---|---|
| 自定义字段 | ✅ `params` 是 `Mixed`，**支持** |
| `type` 枚举 | ❌ **不支持** —— 须扩 enum |
| `deviceId`/`channelCode` | ❌ **required** —— 须补 |
| TTL | ⚠️ **90 天** —— 秒级延迟无影响，需加断言 |
| 索引 | ✅ 现成可用 |
| **原方案结论** | ⚠️ **需修正**（我原写的 `runAt` 顶层字段 + `region_switch` 直接可用，**是错的**） |

## 四、残余局限（本轮未能闭合）

1. **字段类型未逐项比对** —— 如 v21998 `collectThreshold: {eth:0.001,usdt:1}`（对象）
   vs gasleak `threshold`（Number）。**类型差异可能需迁移脚本。**

2. **未找到版本号级谱系证据** —— gasleak `package.json` 为
   `name:"server", version:"1.0.0"`，无 `v21998` 字样。
   两处均无构建 ID / git commit / 时间戳可比对。
   **谱系结论基于代码指纹，而非版本号。**

3. **未验证 `Task` 模型是否能承载 wallet 级任务** ——
   `deviceId` required 是设计假设，实际可能需改 model（如允许 null）。

4. **未验证 gasleak 的 `Task` 下发链路** ——
   若 `region_switch` 任务被 `/taskget` 下发到**设备**，会造成语义错误
   （设备不理解 region 概念）。**需在下发侧过滤。**

5. **未比对索引定义** —— 仅比对了字段名，索引差异未核。

6. **`chainconfigs` 的迁移映射未验证** ——
   `collectAddress` → `collect-config.address`？字段语义需实测确认。

7. **仍未编译、未运行、未真机验证** —— 全部为静态分析 + 离线密码学验证。
