## 三、关键版本门禁（源码原文）

### 3.1 Filza 第 1/2 代：硬 `exit(1)`

`kexploit/offsets.m:189`：

```objc
void offsets_init(void) {
    if (!(SYSTEM_VERSION_GREATER_THAN_OR_EQUAL_TO(@"17.0") &&
          SYSTEM_VERSION_LESS_THAN(@"26.1"))) {
        printf("[-] Only supported offset for iOS/iPadOS 17.0 - 26.0.x\n");
        exit(EXIT_FAILURE);              // ★ 硬退出，进程终止
    }
    ...
```

**调用位置**：`kexploit_opa334.m:913-915`

```objc
int kexploit_opa334(void) {
    offsets_init();                      // ★ 第一件事，先门禁
    ...
```

**已验证**：反汇编 `_kexploit_opa334@0x1abe0` 第一条调用就是 `bl _offsets_init@0x1bd88`。

### 3.2 一个"看似矛盾"的澄清

`kexploit_opa334.m:949-955` 里有 iOS 15.x / 16.x / 26.x 分支：

```objc
if (SYSTEM_VERSION_GREATER_THAN_OR_EQUAL_TO(@"16.0") &&
    SYSTEM_VERSION_LESS_THAN(@"19.0") && ... ) break;   // iOS 16/17/18
if (SYSTEM_VERSION_GREATER_THAN_OR_EQUAL_TO(@"26.0") && ...) break;  // iOS 26.x
if (SYSTEM_VERSION_LESS_THAN(@"16.0")) break;                        // iOS 15.x
```

但**这段在 17.0–26.0.x 之外永远不会执行**——因为前面 `offsets_init()` 已经 `exit(1)`。

→ **`SYSTEM_VERSION_LESS_THAN(@"16.0")` 是死代码**（该路径不可达）。

## 四、第 3 代为何"无版本限制"

`MCMBridge.m` 用 **dlsym 运行时探测** API 存在性，不写版本判断：

```objc
api.handle = dlopen("/usr/lib/system/libsystem_containermanager.dylib",
                    RTLD_NOW | RTLD_LOCAL);
LOAD(queryCreate,        "container_query_create");
LOAD(querySetPart,       "container_query_operation_set_part");   // iOS 18 无此符号
LOAD(querySetPartDomain, "container_query_operation_set_part_domain");

// iOS 18 does not export the part API. A new query already defaults to
// part 0, so only set it when the newer API is present.
if (api->querySetPart) api->querySetPart(query, 0);
```

`MCMBridgeAvailable()` 检查必需符号是否齐全，缺失则优雅降级 ——
**这就是它能跨 18/26/27 的原因**。

**代价**（作者自述边界）：

> Boundary: no arbitrary /var, Keychain, TCC, root, kernel, or app-bundle access is claimed.

## 六、一句话回答

> **当前支持范围：**
> **链**：15.2–17.2.1（coruna）、18.4–18.4.1（darksword 完整）、18.5–18.6.2（仅前段）
> **Filza 第 1/2 代**：17.0 – 26.0.x（硬门禁，超出即 `exit(1)`）
> **Filza 第 3 代**：无版本限制，实测到 27 beta 4
>
> **端到端完整可用**：**17.0–17.2.1** 与 **18.4–18.4.1**
> **17.3–18.3.x 与 18.7+**：工具能用，但**没有链能把注入前提做出来**

## 七、扩展覆盖需要什么

| 目标 | 可行性 | 需要的材料 |
|---|---|---|
| 15.2–16.x 用第 1/2 代 | **改一行**：放宽 `offsets_init` 门禁 | 但需补 16.x 偏移（当前无 15/16 段） |
| 26.1+ 用第 1/2 代 | 需扩展偏移阶梯 | KDK 对照提取新偏移 |
| 17.3–18.3.x 可用 | **需新链** | 两链均无此段偏移 |
| 18.5–18.6.2 全链 | 需补 **sbx0 偏移 + RCE 模块** | 两者缺一不可，需固件提取 |
| 支持 iPad | 两链机型表均无 iPad | 需另行获取 |

## 八、证据局限

1. **未编译、未运行、未真机验证**。
2. README 与 `offsets.m` 门禁**表述不一致**（README 说 "iOS 18, iOS 26, iOS 27 beta"，
   门禁写 `17.0 - 26.0.x`）—— 本文以**源码门禁为准**。
3. `27 beta 4` 只在 **MobileGestalt 类 13 PoC** 的 README 实测表中出现，
   **第 1/2 代内核链在 27 上不可用**（门禁 < 26.1）。
4. 第 3 代"无版本限制"是基于**无版本判断代码 + dlsym 探测**的推断，
   旧版本上 ContainerManager API 是否齐全**未逐一验证**。
5. Filza dylib 的 `minos=15.0.0` 是**声明最低值**；
   实际受 `offsets_init` 门禁约束为 17.0+。
